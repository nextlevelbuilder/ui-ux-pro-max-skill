## Nouveautés de la v2.0

### Génération intelligente de design system

La fonctionnalité phare de la v2.0 est le **Générateur de design system** : un moteur de raisonnement propulsé par l'IA qui analyse les besoins de votre projet et génère en quelques secondes un design system complet et sur mesure.

│     • Associer produit → règles de catégorie UI                 │

### 192 règles de raisonnement spécifiques à chaque secteur

Le moteur de raisonnement comprend des règles spécialisées pour :

| Catégorie | Exemples |
|----------|----------|
| **Tech & SaaS** | SaaS, Micro SaaS, service B2B, outil de développement / IDE, plateforme IA/chatbot, plateforme de cybersécurité |
| **Finance** | Fintech/crypto, banque, assurance, suivi des finances personnelles, outil de factures et de facturation |
| **Santé** | Clinique médicale, pharmacie, dentaire, vétérinaire, santé mentale, rappel de médicaments |
| **E-commerce** | Généraliste, luxe, marketplace (P2P), box par abonnement, livraison de repas |
| **Services** | Beauté/spa, restaurant, hôtel, juridique, services à domicile, réservation et prise de rendez-vous |
| **Créatif** | Portfolio, agence, photographie, jeux vidéo, streaming musical, éditeur photo/vidéo |
| **Lifestyle** | Suivi d'habitudes, recettes et cuisine, méditation, météo, journal intime, suivi de l'humeur |
| **Technologies émergentes** | Web3/NFT, informatique spatiale, informatique quantique, flotte de drones autonomes |

Chaque règle comprend :
- **Pattern recommandé** - Structure de la landing page
- **Priorité de style** - Styles d'interface les plus adaptés
- **Ambiance colorimétrique** - Palettes adaptées au secteur
- **Ambiance typographique** - Personnalité des polices
- **Effets clés** - Animations et interactions
- **Anti-patterns** - Ce qu'il ne faut PAS faire (p. ex. « dégradés IA violet/rose » pour une banque)

## Fonctionnalités

- **80 styles d'interface consultables (51 actifs)** - Glassmorphism, Claymorphism, Minimalisme, Brutalisme, Neumorphism, Bento Grid, mode sombre, AI-Native UI, et bien d'autres
- **192 palettes de couleurs** - Palettes sectorielles alignées 1:1 sur les 192 types de produits
- **74 associations de polices** - Combinaisons typographiques sélectionnées, avec imports Google Fonts
- **25 types de graphiques** - Recommandations pour tableaux de bord et analytique
- **22 stacks techniques** - React, Next.js, Astro, Vue, Nuxt.js, Nuxt UI, Svelte, SwiftUI, React Native, Flutter, HTML+Tailwind, shadcn/ui, Jetpack Compose, Angular, Laravel, Three.js, JavaFX, WPF, WinUI 3, UWP, Avalonia, Uno Platform
- **120 recommandations UX** - Bonnes pratiques, anti-patterns, règles d'accessibilité, mise en page de texte robuste, libellés compacts et interactions annulables. Voir [Raccourcis Entrée compatibles IME](docs/ime-composition.md).
- **192 règles de raisonnement** - Génération de design system spécifique à chaque secteur (NOUVEAU en v2.0)

### Texte robuste et interface compacte

Les recommandations couvrent désormais les défaillances courantes en production concernant les titres, les chaînes longues, les chips, les badges et les micro-interactions interrompues :

- L'équilibrage du retour à la ligne des titres est une amélioration progressive, et non une garantie qu'un mot précis restera sur la dernière ligne. Les designs doivent fonctionner avec un retour à la ligne naturel, quels que soient la largeur, la police et la langue.
- Le texte essentiel doit se réorganiser sans être tronqué sur les écrans étroits, avec le zoom du navigateur, l'agrandissement du texte et les espacements personnalisés par l'utilisateur. Les URL et identifiants longs peuvent passer à la ligne en toute sécurité.
- Les collections de chips et de tags doivent passer à la ligne ou utiliser un bouton `+n` fonctionnel pour afficher le reste. Un libellé compact doit rester entier lorsque c'est possible ; une troncature inévitable nécessite un moyen accessible d'afficher la valeur complète, au clavier, à la souris et au toucher.
- Le sens d'un badge ne peut pas reposer uniquement sur la couleur. Les chips interactives nécessitent une sémantique native, un focus visible et un état exposé programmatiquement ; les compteurs dynamiques ont besoin d'un contexte explicite.
- Des interactions rapides peuvent interrompre une animation, mais l'état sémantique final, le focus et le contenu doivent rester corrects. Le timing est choisi selon la plateforme et le composant, en respectant les préférences de réduction des animations.

### Taxonomie des styles

Le catalogue contient **80 styles consultables**, reposant sur des identifiants stables et des alias :

| Statut | Nombre | Comportement de recherche |
|--------|------:|-----------------|
| Actif | 51 | Inclus dans les recommandations normales et affiché par défaut dans la galerie |
| Complémentaire | 29 | Renvoyé en cas de demande exacte ou explicite de variante/système ; disponible via le filtre de statut de la galerie |
| Obsolète | 9 | Exclu du classement normal ; les anciens noms redirigent vers un style canonique ou un pattern de landing page |

L'ensemble actif couvre 43 familles visuelles générales, 2 styles propres au mobile, 4 systèmes de design officiels de plateformes, 1 matériau de plateforme et 1 style analytique de base. Les systèmes officiels actuels comprennent Fluent 2, Shopify Polaris, Adobe Spectrum et Apple Native Experience ; Liquid Glass est défini comme un matériau de la plateforme Apple, Material 3 Expressive reste une variante mobile de Material, et Spectrum 2 est complémentaire. Les structures de landing page sont regroupées dans un jeu de données distinct de 34 patterns, plutôt que d'entrer en concurrence avec les styles visuels dans le classement BM25.

Voir [`styles.csv`](src/ui-ux-pro-max/data/styles.csv) pour la taxonomie complète et les métadonnées de provenance.

### Appliquer un thème à une application existante

Après avoir [installé le skill](#installation), ouvrez votre application dans votre assistant IA et utilisez un prompt comme celui-ci. En mode Workflow, préfixez-le avec `/ui-ux-pro-max`.

```text
Utilise le skill ui-ux-pro-max pour changer le thème de mon application React existante.
Style cible : Minimalism & Swiss Style.
Commence par examiner les versions du framework et de la bibliothèque de styles, les routes,
les composants, les styles et les tokens de thème existants. Conserve la structure actuelle
des composants, leur comportement et la logique métier.
Réutilise et mets à jour les tokens sémantiques existants pour les couleurs, la typographie,
les espacements, les rayons, les ombres et les états d'interaction ; ajoute les tokens manquants
plutôt que de créer un système de thème parallèle. Remplace les styles codés en dur un composant
à la fois.
Vérifie le contraste, le focus clavier, les mises en page responsive et tous les modes clair/sombre
pris en charge. Résume les fichiers modifiés et les styles codés en dur restants.
```

Remplacez `Minimalism & Swiss Style` par le [style du catalogue](src/ui-ux-pro-max/data/styles.csv) ou la direction visuelle de votre choix. Les résultats de recherche fournissent des recommandations de design ; ils ne réécrivent pas automatiquement votre application.

**Check-list de migration de thème :**

- **Auditer :** repérez les valeurs codées en dur liées au thème dans les feuilles de style, les styles inline et les classes utilitaires comme `bg-blue-600` ou `text-[#1e293b]`.
- **Associer :** réutilisez des rôles sémantiques tels que `background`, `surface`, `foreground`, `primary`, `border` et `ring` dans le système de styles existant de l'application. Ajoutez les rôles manquants en suivant les conventions de la version installée de sa bibliothèque.
- **Migrer :** remplacez les valeurs codées en dur par des références aux tokens, par petits lots de composants. Modifier uniquement les tokens n'aura aucun effet sur les styles qui ne les utilisent pas.
- **Vérifier :** contrôlez le contraste du texte et de l'interface, les états de survol/focus/désactivé, les mises en page responsive et chaque thème pris en charge après chaque lot.

### Comment ça marche

1. **Vous demandez** - Formulez n'importe quelle tâche d'UI/UX (créer, concevoir, implémenter, relire, corriger, améliorer)
2. **Génération du design system** - L'IA génère automatiquement un design system complet grâce au moteur de raisonnement
3. **Recommandations intelligentes** - En fonction de votre type de produit et de vos besoins, il trouve les styles, couleurs et typographies les plus adaptés
4. **Génération du code** - Implémente l'interface avec les bonnes couleurs, polices, espacements et bonnes pratiques
5. **Vérifications avant livraison** - Contrôle le résultat par rapport aux anti-patterns UI/UX courants

### Compatibilité RTL (`--rtl`)

Chaque ligne de style et de produit comporte un `rtl_level` pour les interfaces de droite à gauche (arabe, hébreu, persan, ourdou) :

| Niveau | Signification |
|-------|---------|
| `full` | Indépendant du sens de lecture : la mise en page supporte l'inversion sans modification. |
| `partial` | S'inverse proprement, mais certains composants et animations doivent être ajustés. |
| `caveats` | Le style ou le produit encode le sens de lecture (typographie cinétique, frises chronologiques LTR, surfaces de code/terminal, cartes et ordre des sièges). |

```bash
# Uniquement les styles qui s'inversent sans travail supplémentaire
python3 .claude/skills/ui-ux-pro-max/scripts/search.py "dashboard" --domain style --rtl=full

# Tous les niveaux, résultats filtrés toujours étiquetés avec rtl_level
python3 .claude/skills/ui-ux-pro-max/scripts/search.py "mobile" --domain style --rtl
```

`--rtl` nécessite un `--domain style` ou `--domain product` explicite. Le filtre est appliqué après le classement mais avant la troncature `-n/--max-results`, de sorte qu'une limite étroite ne masque jamais une ligne correspondante. Il est refusé avec `--design-system` et `--stack`.

### Persister le design system (pattern Master + Overrides)

Enregistrez votre design system dans des fichiers pour une **récupération hiérarchique d'une session à l'autre** :

```bash
# Générer et enregistrer dans design-system/myapp/MASTER.md
python3 .claude/skills/ui-ux-pro-max/scripts/search.py "SaaS dashboard" --design-system --persist -p "MyApp"

# Créer également un fichier de surcharge propre à une page
python3 .claude/skills/ui-ux-pro-max/scripts/search.py "SaaS dashboard" --design-system --persist -p "MyApp" --page "dashboard"
```

Cela crée une arborescence `design-system/` :

```
design-system/
└── myapp/                  # Un dossier par projet (slug de -p "MyApp")
    ├── MASTER.md           # Source de vérité globale (couleurs, typographie, espacements, composants)
    └── pages/
        └── dashboard.md    # Surcharges propres à la page (uniquement les écarts par rapport au Master)
```

**Fonctionnement de la récupération hiérarchique :**
1. Lorsque vous créez une page précise (p. ex. « Checkout »), vérifiez d'abord `design-system/[project-slug]/pages/checkout.md`
2. Si le fichier de la page existe, ses règles **remplacent** celles du fichier Master
3. Sinon, utilisez exclusivement `design-system/[project-slug]/MASTER.md`

**Prompt de récupération contextuelle :**
```
Je crée la page [Nom de la page]. Lis design-system/[project-slug]/MASTER.md.
Vérifie aussi si design-system/[project-slug]/pages/[page-name].md existe.
Si le fichier de la page existe, donne la priorité à ses règles.
Sinon, utilise exclusivement les règles du Master.
Maintenant, génère le code...
```

## Architecture et contribution

### Pour les utilisateurs

Le code a été restructuré autour d'un **système de génération à base de templates**. Tous les fichiers propres à chaque plateforme (`.cursor/`, `.windsurf/`, `.kiro/`, `.factory/`, etc.) sont désormais générés dynamiquement par la CLI.

**Utilisez toujours la CLI pour installer :**

```bash
npm install -g ui-ux-pro-max-cli
uipro init --ai <platform>
```

Vous obtenez ainsi les derniers templates fournis avec le paquet CLI installé, ainsi que la structure de fichiers adaptée à votre assistant IA. Mettez d'abord à jour le paquet npm lorsqu'une nouvelle version est publiée.

### Provenance et actualisation des catalogues

Le résumé de catalogue versionné recense actuellement **1 934 Google Fonts approuvées** ainsi que **8 exclusions en attente de revue**, qui ne sont pas promues tant qu'elles n'ont pas de métadonnées de licence officielles correspondantes. Les recommandations d'icônes restent à **105 lignes sélectionnées** (100 imports web Phosphor directs plus des recommandations React Native/de repli) ; le **manifeste Phosphor amont de 1 512 icônes**, distinct, valide les noms, les graisses et les imports React/SSR sans inonder les résultats de recherche avec l'intégralité du paquet amont.

Le développement courant et la CI des pull requests ne dépendent pas du réseau. Lancez la vérification hors ligne complète, y compris les hachages des snapshots et la validation des comptes générés, avec :

```bash
npm --prefix cli run verify:data
# Ou vérifier uniquement le résumé de catalogue généré :
npm --prefix cli run validate:catalog-summary
```

La normalisation de l'actualisation peut également être testée entièrement hors ligne à partir des fixtures versionnées. Les résultats sont écrits dans un répertoire candidat temporaire et ne remplacent jamais les données canoniques :

```bash
candidate_dir="$(mktemp -d)"
python3 scripts/refresh-google-fonts.py \
  --api-input src/ui-ux-pro-max/scripts/tests/fixtures/catalogs/google-api.json \
  --metadata-input src/ui-ux-pro-max/scripts/tests/fixtures/catalogs/google-metadata.json \
  --existing-csv src/ui-ux-pro-max/scripts/tests/fixtures/catalogs/google-existing.csv \
  --overrides src/ui-ux-pro-max/scripts/tests/fixtures/catalogs/google-overrides.json \
  --output-csv "$candidate_dir/google-fonts.csv" \
  --license-output "$candidate_dir/google-font-licenses.json" \
  --metadata-revision fixture-catalogs-v1 \
  --verified-at 2026-08-13 --expected-count 2 --approve-changes
python3 scripts/refresh-icon-catalog.py \
  --input src/ui-ux-pro-max/scripts/tests/fixtures/catalogs/phosphor-core.json \
  --package-json src/ui-ux-pro-max/scripts/tests/fixtures/catalogs/phosphor-package.json \
  --react-package-json src/ui-ux-pro-max/scripts/tests/fixtures/catalogs/phosphor-react-package.json \
  --react-exports-input src/ui-ux-pro-max/scripts/tests/fixtures/catalogs/phosphor-react-exports.json \
  --curated-csv src/ui-ux-pro-max/scripts/tests/fixtures/catalogs/icons-curated.csv \
  --output "$candidate_dir/phosphor-icons-upstream.json" \
  --verified-at 2026-08-13 --expected-count 2
```

L'actualisation en direct depuis les sources amont est volontairement isolée dans le workflow `refresh-catalogs.yml`, planifié le lundi à 03h17 UTC et également disponible à la demande. Configurez `GOOGLE_FONTS_API_KEY` comme secret GitHub Actions, puis lancez le workflow et téléchargez son artefact de revue :

```bash
gh workflow run refresh-catalogs.yml
run_id="$(gh run list --workflow refresh-catalogs.yml --limit 1 --json databaseId --jq '.[0].databaseId')"
gh run watch "$run_id"
gh run download "$run_id" --name "catalog-refresh-review-$run_id"
```

Le workflow interroge l'API Google Fonts Developer et les paquets Phosphor officiels à version figée, écrit les fichiers candidats et les diffs unifiés dans un artefact, et ne dispose que de permissions en lecture seule sur le dépôt. Il ne fait jamais de commit, de push, n'ouvre jamais de PR et ne fusionne jamais rien. Examinez les rapports de modifications, les exclusions, les licences, les métriques de pertinence et la vérification hors ligne avant de promouvoir manuellement les fichiers candidats dans `src/ui-ux-pro-max/data/`.


## Releases automatisées

Ce dépôt utilise semantic-release avec les Conventional Commits pour créer automatiquement les releases GitHub :

- La branche `dev` crée des pré-versions bêta GitHub, comme `2.6.0-beta.1`.
- La branche `main` crée des versions stables officielles GitHub, comme `2.6.0`.

Les notes de version et le `CHANGELOG.md` sont générés à partir des messages de commit au format Conventional Commits. Les numéros de version sont synchronisés entre `skill.json`, `.claude-plugin/plugin.json`, `.claude-plugin/marketplace.json`, `cli/package.json` et `cli/package-lock.json` lors de la préparation de la release.

Utilisez ces types de commit pour obtenir le bon incrément de version :

- `fix:` -> version corrective (patch)
- `feat:` -> version mineure
- `feat!:` ou `BREAKING CHANGE:` -> version majeure

Le workflow de release utilise le `GITHUB_TOKEN` par défaut pour les releases GitHub et le secret `NPM_TOKEN` du dépôt pour publier `ui-ux-pro-max-cli` sur npm.

## Dépannage

### Claude Code signale `response exceeded the ... output token maximum`

Il s'agit d'une limite propre à une seule réponse de Claude Code, et non d'une erreur de l'installeur ou des scripts de recherche d'UI/UX Pro Max. Demandez d'abord à Claude de découper la tâche en étapes plus petites et d'écrire les résultats volumineux dans des fichiers au fur et à mesure.

Si vous avez réellement besoin d'une réponse unique plus longue et que le modèle actif le permet, définissez la limite de tokens de sortie de Claude Code avant de démarrer une nouvelle session. Par exemple :

```bash
# macOS, Linux ou WSL
export CLAUDE_CODE_MAX_OUTPUT_TOKENS="64000"
claude
```

```powershell
# Windows PowerShell
$env:CLAUDE_CODE_MAX_OUTPUT_TOKENS = "64000"
claude
```

Les modifications de l'environnement du shell ne s'appliquent qu'aux programmes lancés depuis ce shell : redémarrez donc Claude Code après avoir défini la variable. Claude Code plafonne les valeurs supérieures à la limite de sortie du modèle actif ; les plafonds varient selon le modèle et le fournisseur. Augmenter cette valeur peut aussi accroître la latence et la consommation, et réduit le contexte effectivement disponible avant la compaction automatique. Consultez la [référence officielle des variables d'environnement de Claude Code](https://code.claude.com/docs/en/env-vars#variables).

### `uipro: unknown command 'uninstall'` ou `unknown command 'update'`

Votre version installée de `ui-ux-pro-max-cli` est obsolète. Mettez-la à jour et réessayez :

```bash
npm install -g ui-ux-pro-max-cli@latest
uipro uninstall
```

### `uipro uninstall` affiche « No installed AI skill directories detected »

Le skill a été installé dans un autre répertoire que celui depuis lequel vous lancez la commande. Au choix :

```bash
# Option A — lancer la commande depuis la racine du projet où vous l'avez installé
cd /path/to/your/project
uipro uninstall

# Option B — supprimer l'installation globale
uipro uninstall --global

# Option C — supprimer manuellement
rm -rf .claude/skills/ui-ux-pro-max   # Claude Code
rm -rf .cursor/skills/ui-ux-pro-max   # Cursor
rm -rf .windsurf/skills/ui-ux-pro-max # Windsurf
rm -rf .agents/skills/ui-ux-pro-max   # Antigravity / Codex
```

### La boîte de dialogue « Upload a skill » de Claude.ai affiche « Zip contains too many files (maximum 200) »

N'envoyez pas le ZIP complet du dépôt GitHub. Il s'agit d'une copie de développement qui contient le code source, les ressources de la CLI, la documentation, des aperçus et plusieurs skills intégrés : elle dépasse donc la limite de 200 fichiers de Claude. Ce n'est pas un artefact destiné à l'envoi d'un skill sur Claude, et ce projet ne publie pas actuellement de ZIP distinct pour un envoi manuel sur Claude.ai.

Pour Claude Code, installez-le via la Marketplace :

```bash
/plugin marketplace add nextlevelbuilder/ui-ux-pro-max-skill
/plugin install ui-ux-pro-max@ui-ux-pro-max-skill
```

Ou utilisez l'installeur CLI :

```bash
npx ui-ux-pro-max-cli init --ai claude
```

### L'installation via la Claude Marketplace échoue avec « Zip file contains a symbolic link »

Il s'agit d'un problème connu des versions antérieures à la v2.5.1. Le dépôt utilisait en interne des liens symboliques que certains outils d'installation ne savent pas gérer. **Solution :** utilisez plutôt l'installeur CLI :

```bash
npm install -g ui-ux-pro-max-cli
uipro init --ai claude
```

Ou attendez la prochaine version, dans laquelle ce problème est corrigé.

### `npm install -g ui-ux-pro-max-cli` échoue avec une erreur de permissions

Utilisez un gestionnaire de versions de Node (recommandé), ou évitez complètement l'installation globale :

```bash
# npx sans installation globale
npx ui-ux-pro-max-cli init --ai claude
```

### Python introuvable lors de l'exécution des commandes de design system

Les scripts de recherche nécessitent Python 3.x. Installez-le manuellement depuis [python.org](https://www.python.org/downloads/) ou avec le gestionnaire de paquets de votre système (Homebrew, apt, winget). Les agents IA ne doivent pas l'installer à votre place : ils ont pour consigne de vous le demander.

### La sortie du design system est coupée / les champs sont tronqués

La sortie lisible par un humain tronque les champs longs à 300 caractères. Utilisez `--json` pour obtenir les données complètes, sans troncature :

```bash
python3 .claude/skills/ui-ux-pro-max/scripts/search.py "SaaS" --domain style --json
```
