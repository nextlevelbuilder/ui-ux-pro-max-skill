### 192 條產業專屬推理規則

推理引擎內建以下類別的專屬規則：

| 類別 | 範例 |
|------|------|
| **科技與 SaaS** | SaaS、Micro SaaS、B2B 服務、開發者工具 / IDE、AI / 聊天機器人平台、資安平台 |
| **金融** | Fintech / 加密貨幣、銀行、保險、個人財務追蹤、發票與帳務工具 |
| **醫療保健** | 醫療診所、藥局、牙科、獸醫、心理健康、用藥提醒 |
| **電子商務** | 一般、精品、市集（P2P）、訂閱盒、外送 |
| **服務業** | 美容 / SPA、餐廳、飯店、法律、居家服務、預約與訂位 |
| **創意** | 作品集、設計 / 行銷公司、攝影、遊戲、音樂串流、照片 / 影片編輯 |
| **生活風格** | 習慣追蹤、食譜與烹飪、冥想、天氣、日記、心情追蹤 |
| **新興科技** | Web3 / NFT、空間運算、量子運算、自主無人機機隊 |

每條規則包含：
- **建議模式（Recommended Pattern）**：landing page 結構
- **風格優先順序（Style Priority）**：最合適的 UI 風格
- **色彩調性（Color Mood）**：符合產業的配色
- **字體調性（Typography Mood）**：字體個性的搭配
- **關鍵效果（Key Effects）**：動畫與互動
- **反模式（Anti-Patterns）**：不該做的事，例如銀行業要避免「AI 紫 / 粉紅漸層」

## 功能特色

- **79 種可搜尋的 UI 風格（50 種 active）**：Glassmorphism、Claymorphism、Minimalism、Brutalism、Neumorphism、Bento Grid、Dark Mode、AI-Native UI 等
- **192 組配色**：依產業設計，與 192 種產品類型一一對應
- **74 組字體搭配**：精選字體組合，附 Google Fonts 匯入程式碼
- **25 種圖表類型**：針對儀表板與數據分析的建議
- **22 種技術堆疊**：React、Next.js、Astro、Vue、Nuxt.js、Nuxt UI、Svelte、SwiftUI、React Native、Flutter、HTML+Tailwind、shadcn/ui、Jetpack Compose、Angular、Laravel、Three.js、JavaFX、WPF、WinUI 3、UWP、Avalonia、Uno Platform
- **119 條 UX 指南**：最佳實踐、反模式、無障礙規則、具容錯性的文字版面、精簡標籤與可取消的互動
- **192 條推理規則**：依產業生成設計系統（v2.0 新增）

### 具容錯性的文字與精簡 UI

指南現已涵蓋正式環境中常見的問題：標題、超長 token、chip、badge，以及被打斷的微互動。

- 標題平衡換行是漸進式增強，不保證特定字詞會留在最後一行。設計仍須在不同寬度、字體與語系下，以自然換行正常運作。
- 重要文字必須能在窄寬度、瀏覽器縮放、文字縮放與使用者自訂間距下重新排版而不被截斷。超長 URL 與識別碼可以安全換行。
- chip 與 tag 集合應該換行，或提供可操作的 `+n` 展開。精簡標籤在可行時應保持完整；若無法避免截斷，必須為鍵盤、滑鼠與觸控使用者提供可存取的完整內容。
- badge 的意義不能只靠顏色傳達。互動式 chip 需要原生語意、可見的焦點與可由程式讀取的狀態；即時更新的數字需要有意義的上下文。
- 快速互動可以取消動畫，但最終的語意狀態、焦點與內容必須正確。動畫時間依平台與元件選擇，並尊重減少動態效果的偏好設定。

### 風格分類

目錄包含 **79 種可搜尋風格**，皆有穩定的 ID 與別名：

| 狀態 | 數量 | 搜尋行為 |
|------|-----:|----------|
| Active | 50 | 納入一般推薦，並預設顯示於 gallery |
| Supplemental | 29 | 只在明確指定的變體 / 系統需求時回傳；可透過 gallery 的狀態篩選器查看 |
| Deprecated | 9 | 不參與一般排序；舊名稱會導向標準風格或 landing page 模式 |

active 風格涵蓋 43 種一般視覺家族、2 種行動裝置專用風格、3 種官方平台 / 設計系統、1 種平台材質，以及 1 種核心分析風格。目前的官方系統包括 Fluent 2、Shopify Polaris 與 Adobe Spectrum；Liquid Glass 定位為 Apple 平台材質，Material 3 Expressive 維持為行動裝置的 Material 變體，Spectrum 2 為 supplemental。Landing page 結構放在獨立的 34 種模式資料集，不與視覺風格一起參與 BM25 排序。

完整分類與附出處的中繼資料請見 [`styles.csv`](src/ui-ux-pro-max/data/styles.csv)。

## 💎 基本版與進階版比較

許多使用者會問開源版與進階版有什麼差別。以下是詳細說明，協助你選擇適合自己工作流程的版本。

### 🟢 基本版（本儲存庫）
* **完全開源**：適合個人開發者、愛好者與一般專案。
* **核心 UI/UX 智慧**：可完整使用 79 種可搜尋 UI 風格（50 種 active）、192 種產品類型、配色與精選字體搭配。
* **智慧推薦**：內建 BM25 搜尋引擎，設計比對精準。
* **跨平台支援**：針對 22 個主流框架提供專屬指南（React、Vue、Tailwind、iOS、Android 等）。
* **設計系統生成**：透過 CLI 立即生成量身打造的 UI 規則、模式與邏輯。

### 🟡 進階版
* **延伸品牌設計技能**：不只 UI/UX，還包含品牌識別生成、Logo 設計、企業識別系統（CIP）、橫幅、簡報與自訂圖示。
* **進階素材製作**：深度整合 AI 影像生成，產出真實的視覺素材，而非佔位圖。
* **企業級架構**：更完整、可擴充的 Design Token 架構，為大型團隊部署而設計。
* **優先支援**：為需要完整、不中斷設計流程的團隊與專業人士提供專屬技術協助。

👉 *想進一步了解如何升級到進階版，請造訪 [uupm.cc](https://uupm.cc)。*

### 為現有應用程式套用主題

[安裝 skill](#安裝) 之後，在 AI 助手中開啟你的應用程式，使用類似下面的提示詞。Workflow 模式請在前面加上 `/ui-ux-pro-max`。

```text
Use the ui-ux-pro-max skill to retheme my existing React app.
Target style: Minimalism & Swiss Style.
First inspect the framework and styling-library versions, routes, components,
styles, and existing theme tokens. Keep the current component structure,
behavior, and business logic.
Reuse and update the existing semantic tokens for colors, typography, spacing,
radii, shadows, and interaction states; add missing tokens rather than creating
a parallel theme system. Replace hard-coded styles one component at a time.
Verify contrast, keyboard focus, responsive layouts, and all supported light/dark
modes. Summarize changed files and any remaining hard-coded styles.
```

把 `Minimalism & Swiss Style` 換成你偏好的[目錄風格](src/ui-ux-pro-max/data/styles.csv)或視覺方向。搜尋結果只提供設計指引，不會自動改寫你的應用程式。

**主題遷移檢查清單：**

- **盤點（Audit）**：找出樣式表、inline style，以及 `bg-blue-600` 或 `text-[#1e293b]` 這類 utility 中與主題相關的寫死數值。
- **對應（Map）**：在應用程式既有的樣式系統中，重用 `background`、`surface`、`foreground`、`primary`、`border`、`ring` 等語意角色。缺少的角色，依已安裝函式庫版本的慣例補上。
- **遷移（Migrate）**：分小批次把寫死的數值換成 token 參照。只改 token 不會影響沒有使用 token 的樣式。
- **驗證（Verify）**：每一批之後，檢查文字 / UI 對比、hover / focus / disabled 狀態、響應式版面，以及每個支援的主題。

### 運作流程

1. **你提出需求**：任何 UI/UX 工作（建置、設計、建立、實作、審查、修正、改善）
2. **生成設計系統**：AI 透過推理引擎自動生成完整的設計系統
3. **智慧推薦**：依你的產品類型與需求，找出最匹配的風格、配色與字體
4. **產生程式碼**：以正確的色彩、字體、間距與最佳實踐實作 UI
5. **交付前檢查**：依常見 UI/UX 反模式進行驗證

### 保存設計系統（Master + Overrides 模式）

把設計系統存成檔案，讓不同 session 之間可以**分層取用**：

```bash
# 生成並保存到 design-system/myapp/MASTER.md
python3 .claude/skills/ui-ux-pro-max/scripts/search.py "SaaS dashboard" --design-system --persist -p "MyApp"

# 同時建立特定頁面的覆寫檔
python3 .claude/skills/ui-ux-pro-max/scripts/search.py "SaaS dashboard" --design-system --persist -p "MyApp" --page "dashboard"
```

這會建立 `design-system/` 資料夾結構：

```
design-system/
└── myapp/                  # 每個專案一個資料夾（-p "MyApp" 的 slug）
    ├── MASTER.md           # 全域唯一事實來源（色彩、字體、間距、元件）
    └── pages/
        └── dashboard.md    # 頁面專屬覆寫（只記錄與 Master 不同的地方）
```

**分層取用的運作方式：**
1. 建置特定頁面（例如「Checkout」）時，先檢查 `design-system/[project-slug]/pages/checkout.md`
2. 如果頁面檔存在，其規則會**覆寫** Master 檔
3. 如果不存在，就只使用 `design-system/[project-slug]/MASTER.md`

**具上下文感知的取用提示詞：**
```
I am building the [Page Name] page. Please read design-system/[project-slug]/MASTER.md.
Also check if design-system/[project-slug]/pages/[page-name].md exists.
If the page file exists, prioritize its rules.
If not, use the Master rules exclusively.
Now, generate the code...
```

### 目錄出處與更新

已提交的目錄摘要目前記錄了 **1,934 款核准的 Google Fonts**，以及 **8 筆審查排除項目**，這些在沒有對應官方授權中繼資料前不會被納入。圖示指南維持 **105 筆精選資料列**（100 筆直接匯入 Phosphor 的 Web 用法，加上 React Native / 備援指南）；另有獨立的 **1,512 個圖示的上游 Phosphor 清單**，用來驗證名稱、字重與 React / SSR 的匯入方式，同時避免整個上游套件灌爆搜尋結果。

一般開發與 pull request CI 都不依賴網路。要執行完整的離線檢查（包含快照雜湊與生成數量驗證），請執行：

```bash
npm --prefix cli run verify:data
# 或只檢查生成的目錄摘要：
npm --prefix cli run validate:catalog-summary
```

更新流程的正規化也可以完全離線，對已提交的 fixture 執行。輸出會放到暫存的候選資料夾，絕不會取代正式資料：

```bash
candidate_dir="$(mktemp -d)"
python3 scripts/refresh-google-fonts.py \
  --api-input src/ui-ux-pro-max/scripts/tests/fixtures/catalogs/google-api.json \
  --metadata-input src/ui-ux-pro-max/scripts/tests/fixtures/catalogs/google-metadata.json \
  --existing-csv src/ui-ux-pro-max/scripts/tests/fixtures/catalogs/google-existing.csv \
  --overrides src/ui-ux-pro-max/scripts/tests/fixtures/catalogs/google-overrides.json \
  --output-csv "$candidate_dir/google-fonts.csv" \
  --license-output "$candidate_dir/google-font-licenses.json" \
  --metadata-revision fixture-catalogs-v1 \
  --verified-at 2026-08-13 --expected-count 2 --approve-changes
python3 scripts/refresh-icon-catalog.py \
  --input src/ui-ux-pro-max/scripts/tests/fixtures/catalogs/phosphor-core.json \
  --package-json src/ui-ux-pro-max/scripts/tests/fixtures/catalogs/phosphor-package.json \
  --react-package-json src/ui-ux-pro-max/scripts/tests/fixtures/catalogs/phosphor-react-package.json \
  --react-exports-input src/ui-ux-pro-max/scripts/tests/fixtures/catalogs/phosphor-react-exports.json \
  --curated-csv src/ui-ux-pro-max/scripts/tests/fixtures/catalogs/icons-curated.csv \
  --output "$candidate_dir/phosphor-icons-upstream.json" \
  --verified-at 2026-08-13 --expected-count 2
```

即時的上游更新被刻意隔離在 `refresh-catalogs.yml` workflow 中，排程為每週一 03:17 UTC，也可以手動觸發。請先把 `GOOGLE_FONTS_API_KEY` 設為 GitHub Actions secret，然後執行並下載其審查用 artifact：

```bash
gh workflow run refresh-catalogs.yml
run_id="$(gh run list --workflow refresh-catalogs.yml --limit 1 --json databaseId --jq '.[0].databaseId')"
gh run watch "$run_id"
gh run download "$run_id" --name "catalog-refresh-review-$run_id"
```

這個 workflow 會讀取 Google Fonts Developer API 與固定版本的官方 Phosphor 套件，把候選資料與 unified diff 寫入 artifact，且只有唯讀的儲存庫權限。它絕不會 commit、push、開 PR 或 merge。在手動把候選檔案併入 `src/ui-ux-pro-max/data/` 之前，請先審查變更報告、排除項目、授權、相關性指標與離線檢查結果。


## 自動化發布

本儲存庫使用 semantic-release 搭配 Conventional Commits，自動建立 GitHub release：

- `dev` 分支會建立 beta 的 GitHub 預發布版本，例如 `2.6.0-beta.1`。
- `main` 分支會建立正式穩定版的 GitHub release，例如 `2.6.0`。

發布說明與 `CHANGELOG.md` 由 Conventional Commit 訊息生成。版本號會在發布準備階段，同步更新到 `skill.json`、`.claude-plugin/plugin.json`、`.claude-plugin/marketplace.json`、`cli/package.json` 與 `cli/package-lock.json`。

請使用下列 commit 類型，才能得到正確的版本升級：

- `fix:` -> patch 版本
- `feat:` -> minor 版本
- `feat!:` 或 `BREAKING CHANGE:` -> major 版本

發布 workflow 使用預設的 `GITHUB_TOKEN` 建立 GitHub release，並使用儲存庫的 `NPM_TOKEN` secret 把 `ui-ux-pro-max-cli` 發布到 npm。

## 疑難排解

### Claude Code 回報 `response exceeded the ... output token maximum`

這是 Claude Code 單次回應的上限，不是 UI/UX Pro Max 安裝器或搜尋腳本的錯誤。請先請 Claude 把工作拆成較小的步驟，並逐步把大型結果寫入檔案。

如果你確實需要更大的單次回應，而且目前的模型支援，請在開啟新 session 之前設定 Claude Code 的輸出 token 上限。例如：

```bash
# macOS、Linux 或 WSL
export CLAUDE_CODE_MAX_OUTPUT_TOKENS="64000"
claude
```

```powershell
# Windows PowerShell
$env:CLAUDE_CODE_MAX_OUTPUT_TOKENS = "64000"
claude
```

Shell 的環境變數變更只對從該 shell 啟動的程式生效，因此設定後請重新啟動 Claude Code。超過目前模型輸出上限的數值，Claude Code 會自動限縮；各模型與供應商的上限不同。提高這個數值也可能增加延遲與用量，並降低自動壓縮前可用的有效上下文。請參考官方的 [Claude Code 環境變數說明](https://code.claude.com/docs/en/env-vars#variables)。

### `uipro: unknown command 'uninstall'` 或 `unknown command 'update'`

你安裝的 `ui-ux-pro-max-cli` 版本過舊。請更新後再試：

```bash
npm install -g ui-ux-pro-max-cli@latest
uipro uninstall
```

### `uipro uninstall` 顯示 "No installed AI skill directories detected"

skill 安裝的目錄與你執行指令的目錄不同。可以採用以下任一方式：

```bash
# 方式 A：回到當初安裝的專案根目錄執行
cd /path/to/your/project
uipro uninstall

# 方式 B：移除全域安裝
uipro uninstall --global

# 方式 C：手動移除
rm -rf .claude/skills/ui-ux-pro-max   # Claude Code
rm -rf .cursor/skills/ui-ux-pro-max   # Cursor
rm -rf .windsurf/skills/ui-ux-pro-max # Windsurf
rm -rf .agents/skills/ui-ux-pro-max   # Antigravity / Codex
```

### Claude.ai 的「Upload a skill」對話框顯示 "Zip contains too many files (maximum 200)"

請不要上傳整個 GitHub 儲存庫的 ZIP。它是開發用的 checkout，內含原始碼、CLI 資產、文件、預覽與多個打包的 skill，所以會超過 Claude 的 200 個檔案上傳上限。它不是 Claude skill 的上傳檔，本專案目前也沒有提供給 Claude.ai 手動上傳用的獨立 ZIP。

如果使用 Claude Code，請透過 Marketplace 安裝：

```bash
/plugin marketplace add nextlevelbuilder/ui-ux-pro-max-skill
/plugin install ui-ux-pro-max@ui-ux-pro-max-skill
```

或使用 CLI 安裝器：

```bash
npx ui-ux-pro-max-cli init --ai claude
```

### Claude Marketplace 安裝失敗，顯示 "Zip file contains a symbolic link"

這是 v2.5.1 之前版本的已知問題。儲存庫內部使用了 symlink，有些安裝工具無法處理。**解法：**改用 CLI 安裝器：

```bash
npm install -g ui-ux-pro-max-cli
uipro init --ai claude
```

或等待已修正此問題的下一個版本。

### `npm install -g ui-ux-pro-max-cli` 因權限錯誤失敗

建議使用 Node 版本管理工具，或完全跳過全域安裝：

```bash
# 不做全域安裝，直接用 npx
npx ui-ux-pro-max-cli init --ai claude
```

### 執行設計系統指令時找不到 Python

搜尋腳本需要 Python 3.x。請自行從 [python.org](https://www.python.org/downloads/) 或用作業系統的套件管理員（Homebrew、apt、winget）安裝。AI agent 不應該替你安裝，它們會被指示來詢問你。

### 設計系統輸出被截斷 / 欄位被截短

供人閱讀的輸出會把超過 300 個字元的欄位截斷。請使用 `--json` 取得完整、未截斷的資料：

```bash
python3 .claude/skills/ui-ux-pro-max/scripts/search.py "SaaS" --domain style --json
```
