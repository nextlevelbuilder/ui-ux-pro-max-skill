### 192 の業界別推論ルール

推論エンジンには、次の分野向けの専用ルールが含まれています：

| カテゴリ | 例 |
|----------|----------|
| **テック & SaaS** | SaaS、Micro SaaS、B2B サービス、開発者ツール / IDE、AI/チャットボットプラットフォーム、サイバーセキュリティプラットフォーム |
| **金融** | フィンテック/暗号資産、銀行、保険、個人の家計管理、請求書・課金ツール |
| **ヘルスケア** | 医療クリニック、薬局、歯科、動物病院、メンタルヘルス、服薬リマインダー |
| **E コマース** | 一般、ラグジュアリー、マーケットプレイス (P2P)、サブスクリプションボックス、フードデリバリー |
| **サービス** | 美容/スパ、レストラン、ホテル、法律、ホームサービス、予約・アポイントメント |
| **クリエイティブ** | ポートフォリオ、エージェンシー、写真、ゲーム、音楽ストリーミング、写真/動画編集 |
| **ライフスタイル** | 習慣トラッカー、レシピ・料理、瞑想、天気、日記、気分トラッカー |
| **新興テック** | Web3/NFT、空間コンピューティング、量子コンピューティング、自律型ドローン群 |

各ルールには次の内容が含まれます：
- **Recommended Pattern** - ランディングページの構成
- **Style Priority** - 最も適した UI スタイル
- **Color Mood** - 業界にふさわしいパレット
- **Typography Mood** - フォントの個性のマッチング
- **Key Effects** - アニメーションとインタラクション
- **Anti-Patterns** - やってはいけないこと（例：銀行向けの「AI purple/pink gradients」）

## 機能

- **79 の検索可能な UI スタイル（うち 50 が有効）** - Glassmorphism、Claymorphism、Minimalism、Brutalism、Neumorphism、Bento Grid、Dark Mode、AI-Native UI など

- **25 のチャートタイプ** - ダッシュボードや分析向けの推奨
- **22 の技術スタック** - React、Next.js、Astro、Vue、Nuxt.js、Nuxt UI、Svelte、SwiftUI、React Native、Flutter、HTML+Tailwind、shadcn/ui、Jetpack Compose、Angular、Laravel、Three.js、JavaFX、WPF、WinUI 3、UWP、Avalonia、Uno Platform

- **192 の推論ルール** - 業界別のデザインシステム生成（v2.0 の新機能）

### 崩れにくいテキストとコンパクトな UI

見出し、長いトークン、チップ、バッジ、中断されたマイクロインタラクションに関する、
本番環境でよくある不具合もガイダンスでカバーするようになりました：

- 見出しのバランスの取れた折り返しはプログレッシブエンハンスメントであり、特定の単語が
  最終行に残ることを保証するものではありません。デザインは、幅、フォント、ロケールが変わっても、
  自然な折り返しで機能する必要があります。
- 重要なテキストは、狭い幅、ブラウザのズーム、テキストの拡大、ユーザーによる間隔の上書きのもとでも、
  切れずにリフローする必要があります。長い URL や識別子は安全に折り返してかまいません。
- チップやタグの集まりは、折り返すか、操作可能な `+n` の開示を使うべきです。コンパクトな
  ラベルは、可能な限り途切れずに表示されるべきです。やむを得ず省略する場合は、キーボード、ポインター、
  タッチのユーザーが完全な値にアクセスできる手段が必要です。
- バッジの意味を色だけに頼ってはいけません。インタラクティブなチップには、ネイティブのセマンティクス、
  見えるフォーカス、プログラムから取得できる状態が必要です。ライブで変わるカウントには、意味のあるコンテキストが必要です。
- 素早い操作によってアニメーションがキャンセルされることはあっても、最終的なセマンティックな状態、フォーカス、
  コンテンツは正しく保たれなければなりません。タイミングはプラットフォームとコンポーネントに合わせて選び、
  動きを減らす設定を尊重します。

### スタイルの分類

カタログには、安定した ID とエイリアスに裏付けられた **79 の検索可能なスタイル** が含まれています：

| ステータス | 数 | 検索時の動作 |
|--------|------:|-----------------|
| Active | 50 | 通常の推奨に含まれ、ギャラリーでデフォルトで表示されます |
| Supplemental | 29 | 正確な指定や、明示的なバリアント/システムの意図がある場合に返されます。ギャラリーのステータスフィルターから利用できます |
| Deprecated | 9 | 通常のランキングから除外されます。旧名称は正規のスタイルまたはランディングパターンにリダイレクトされます |

Active のセットには、43 の汎用的なビジュアルファミリー、2 つのモバイル専用スタイル、3 つの公式プラットフォーム/デザインシステム、1 つのプラットフォームマテリアル、1 つのコア分析スタイルが含まれます。現在の公式システムには Fluent 2、Shopify Polaris、Adobe Spectrum があります。Liquid Glass は Apple のプラットフォームマテリアルとして扱われ、Material 3 Expressive はモバイルの Material のバリアントのままで、Spectrum 2 は Supplemental です。ランディングページの構成は、BM25 のランキングでビジュアルスタイルと競合しないよう、34 パターンの別のランディングデータセットに分けられています。

完全な分類と、出所を考慮したメタデータについては [`styles.csv`](src/ui-ux-pro-max/data/styles.csv) をご覧ください。

## 💎 ベーシック版とプレミアム版の比較

オープンソース版とプレミアム版の違いについて、多くのご質問をいただいています。ワークフローに合ったものを選べるよう、詳しく説明します。

### 🟢 ベーシック版（このリポジトリ）
* **完全なオープンソース：** 個人の開発者、趣味のプロジェクト、一般的なプロジェクトに最適です。
* **コアの UI/UX インテリジェンス：** 79 の検索可能な UI スタイル（うち 50 が有効）、192 のプロダクトタイプ、カラーパレット、厳選したフォントペアリングをすべて利用できます。
* **スマートな推奨：** 内蔵の BM25 検索エンジンにより、非常に精度の高いデザインのマッチングを行います。
* **クロスプラットフォーム対応：** 22 の主要なフレームワーク（React、Vue、Tailwind、iOS、Android など）に対応したスタック別のガイドライン。
* **デザインシステム生成：** CLI から、ニーズに合わせた UI のルール、パターン、ロジックをすぐに生成できます。

### 🟡 プレミアム版
* **拡張されたブランドデザインスキル：** UI/UX にとどまらず、ブランドアイデンティティの生成、ロゴデザイン、コーポレートアイデンティティプログラム (CIP)、バナー、プレゼンテーションスライド、カスタムのアイコンまでカバーします。
* **高度なアセット作成：** AI を活用した画像生成と深く統合し、プレースホルダーではなく実際のビジュアルアセットを作成します。
* **エンタープライズ向けのアーキテクチャ：** 大規模なチームでの展開に向けた、より包括的でスケーラブルなデザイントークンのアーキテクチャ。
* **優先サポート：** 中断のないデザインワークフロー全体を必要とするチームやプロフェッショナル向けの、専任の技術サポート。

👉 *プレミアム版へのアップグレードについて詳しくは、[uupm.cc](https://uupm.cc) をご覧ください。*

2 つのコマンドで Claude Code に直接インストールできます：


```bash

# Install for your AI assistant

uipro init --ai qoder       # Qoder
uipro init --ai roocode     # Roo Code
uipro init --ai gemini      # Gemini CLI
uipro init --ai trae        # Trae
uipro init --ai opencode    # OpenCode
uipro init --ai continue    # Continue
uipro init --ai codebuddy   # CodeBuddy
uipro init --ai droid       # Droid (Factory)
uipro init --ai kilocode    # KiloCode
uipro init --ai warp        # Warp
uipro init --ai augment     # Augment
uipro init --ai codewhale   # CodeWhale
uipro init --ai zcode       # ZCode
```

npm パッケージの名前は `ui-ux-pro-max-cli` で、インストールされるコマンドは引き続き `uipro` です。古い `uipro-cli` のリリースは更新されておらず、現在のアセットには使わないでください。


## 前提条件

検索スクリプトには Python 3.x が必要です（標準ライブラリのみを使用します。スクリプトは何もインストールせず、ネットワーク通信も行いません）。

Python がインストールされているか確認します：

```bash
python3 --version
```

インストールされていない場合は、[python.org](https://www.python.org/downloads/) から、または OS のパッケージマネージャー（Homebrew、apt、winget）を使ってご自身でインストールしてください。これらのインストール手順は **人間のユーザーであるあなた** のためのものです。このスキルを使う AI エージェントがあなたのマシンにソフトウェアをインストールすることは決してなく、代わりにあなたに依頼するよう指示されています。

### 既存のアプリにテーマを適用する

[スキルをインストール](#インストール)したら、AI アシスタントでアプリを開き、次のようなプロンプトを使ってください。ワークフローモードでは、先頭に `/ui-ux-pro-max` を付けてください。

```text
Use the ui-ux-pro-max skill to retheme my existing React app.
Target style: Minimalism & Swiss Style.
First inspect the framework and styling-library versions, routes, components,
styles, and existing theme tokens. Keep the current component structure,
behavior, and business logic.
Reuse and update the existing semantic tokens for colors, typography, spacing,
radii, shadows, and interaction states; add missing tokens rather than creating
a parallel theme system. Replace hard-coded styles one component at a time.
Verify contrast, keyboard focus, responsive layouts, and all supported light/dark
modes. Summarize changed files and any remaining hard-coded styles.
```

`Minimalism & Swiss Style` は、お好みの[カタログのスタイル](src/ui-ux-pro-max/data/styles.csv)やビジュアルの方向性に置き換えてください。検索結果はデザインのガイダンスを提供するものであり、アプリを自動的に書き換えるものではありません。

**テーマ移行のチェックリスト：**

- **監査：** スタイルシート、インラインスタイル、`bg-blue-600` や `text-[#1e293b]` のようなユーティリティから、テーマに関するハードコードされた値を見つけます。
- **対応付け：** アプリの既存のスタイリングシステムで、`background`、`surface`、`foreground`、`primary`、`border`、`ring` といったセマンティックな役割を再利用します。足りない役割は、インストールされているライブラリのバージョンの慣例に従って追加します。
- **移行：** 小さなコンポーネント単位で、ハードコードされた値をトークンの参照に置き換えます。トークンを変更するだけでは、トークンを使っていないスタイルには反映されません。
- **検証：** 各バッチのあとで、テキスト/UI のコントラスト、ホバー/フォーカス/無効の状態、レスポンシブレイアウト、対応しているすべてのテーマを確認します。

### RTL 互換性 (`--rtl`)

すべてのスタイルとプロダクトの行には、右から左に書く言語のインターフェース
（アラビア語、ヘブライ語、ペルシャ語、ウルドゥー語）向けの `rtl_level` があります：

| レベル | 意味 |
|-------|---------|
| `full` | 方向に依存しません：レイアウトは反転してもそのまま機能します。 |
| `partial` | きれいに反転しますが、個々のコンポーネントやモーションの調整が必要です。 |
| `caveats` | スタイルやプロダクトが読む方向を前提としています（キネティックタイポグラフィ、LTR のタイムライン、コード/ターミナルの画面、地図や座席の並び順など）。 |

```bash
# Only styles that mirror without extra work
python3 .claude/skills/ui-ux-pro-max/scripts/search.py "dashboard" --domain style --rtl=full

# All levels, filtered results still tagged with rtl_level
python3 .claude/skills/ui-ux-pro-max/scripts/search.py "mobile" --domain style --rtl
```

`--rtl` には、明示的な `--domain style` または `--domain product` が必要です。フィルターは
ランキングのあと、`-n/--max-results` による切り詰めの前に適用されるため、上限を小さくしても
一致する行が隠れることはありません。`--design-system` や
`--stack` と一緒に使うことはできません。

### デザインシステムの永続化（Master + Overrides パターン）

デザインシステムをファイルに保存して、**セッションをまたいだ階層的な取得** を行えます：

```bash
# Generate and persist to design-system/myapp/MASTER.md
python3 .claude/skills/ui-ux-pro-max/scripts/search.py "SaaS dashboard" --design-system --persist -p "MyApp"

# Also create a page-specific override file
python3 .claude/skills/ui-ux-pro-max/scripts/search.py "SaaS dashboard" --design-system --persist -p "MyApp" --page "dashboard"
```

これにより、次のような `design-system/` フォルダー構成が作成されます：

```
design-system/
└── myapp/                  # One folder per project (slug of -p "MyApp")
    ├── MASTER.md           # Global Source of Truth (colors, typography, spacing, components)
    └── pages/
        └── dashboard.md    # Page-specific overrides (only deviations from Master)
```

**階層的な取得の仕組み：**
1. 特定のページ（例："Checkout"）を作るときは、まず `design-system/[project-slug]/pages/checkout.md` を確認します
2. ページのファイルが存在する場合、そのルールが Master ファイルを **上書き** します
3. 存在しない場合は、`design-system/[project-slug]/MASTER.md` だけを使います

**コンテキストを考慮した取得のプロンプト：**
```
I am building the [Page Name] page. Please read design-system/[project-slug]/MASTER.md.
Also check if design-system/[project-slug]/pages/[page-name].md exists.
If the page file exists, prioritize its rules.
If not, use the Master rules exclusively.
Now, generate the code...
```

### カタログの出所と更新

コミット済みのカタログの概要には、現在 **1,934 の承認済み Google Fonts** と、
公式のライセンスのメタデータが一致しない限り昇格されない **8 つのレビュー除外** が記録されています。
アイコンのガイダンスは引き続き **105 の厳選した行**（100 の Phosphor の Web 向けの直接のインポートと、
React Native/フォールバックのガイダンス）です。別に用意された
**1,512 アイコンのアップストリームの Phosphor のマニフェスト** は、名前、
ウェイト、React/SSR のインポートを検証するもので、アップストリームのパッケージ全体で検索結果があふれることはありません。

通常の開発とプルリクエストの CI は、ネットワークに依存しません。スナップショットのハッシュと
生成されたカウントの検証を含む、完全なオフラインのゲートは次のコマンドで実行します：

```bash
npm --prefix cli run verify:data
# Or check only the generated catalog summary:
npm --prefix cli run validate:catalog-summary
```

更新の正規化も、コミット済みのフィクスチャに対して完全にオフラインで試すことができます。
出力は一時的な候補ディレクトリに書き出され、正規のデータが
置き換えられることはありません：

```bash
candidate_dir="$(mktemp -d)"
python3 scripts/refresh-google-fonts.py \
  --api-input src/ui-ux-pro-max/scripts/tests/fixtures/catalogs/google-api.json \
  --metadata-input src/ui-ux-pro-max/scripts/tests/fixtures/catalogs/google-metadata.json \
  --existing-csv src/ui-ux-pro-max/scripts/tests/fixtures/catalogs/google-existing.csv \
  --overrides src/ui-ux-pro-max/scripts/tests/fixtures/catalogs/google-overrides.json \
  --output-csv "$candidate_dir/google-fonts.csv" \
  --license-output "$candidate_dir/google-font-licenses.json" \
  --metadata-revision fixture-catalogs-v1 \
  --verified-at 2026-08-13 --expected-count 2 --approve-changes
python3 scripts/refresh-icon-catalog.py \
  --input src/ui-ux-pro-max/scripts/tests/fixtures/catalogs/phosphor-core.json \
  --package-json src/ui-ux-pro-max/scripts/tests/fixtures/catalogs/phosphor-package.json \
  --react-package-json src/ui-ux-pro-max/scripts/tests/fixtures/catalogs/phosphor-react-package.json \
  --react-exports-input src/ui-ux-pro-max/scripts/tests/fixtures/catalogs/phosphor-react-exports.json \
  --curated-csv src/ui-ux-pro-max/scripts/tests/fixtures/catalogs/icons-curated.csv \
  --output "$candidate_dir/phosphor-icons-upstream.json" \
  --verified-at 2026-08-13 --expected-count 2
```

アップストリームからのライブの更新は、意図的に `refresh-catalogs.yml`
ワークフローに分離されています。このワークフローは毎週月曜日の 03:17 UTC に実行されるほか、必要に応じて手動でも実行できます。
GitHub Actions のシークレットとして `GOOGLE_FONTS_API_KEY` を設定し、ワークフローを実行して、
レビュー用のアーティファクトをダウンロードしてください：

```bash
gh workflow run refresh-catalogs.yml
run_id="$(gh run list --workflow refresh-catalogs.yml --limit 1 --json databaseId --jq '.[0].databaseId')"
gh run watch "$run_id"
gh run download "$run_id" --name "catalog-refresh-review-$run_id"
```

このワークフローは Google Fonts Developer API と、バージョンを固定した公式の Phosphor の
パッケージを読み込み、候補と unified diff をアーティファクトに書き出します。リポジトリの権限は読み取り専用です。
コミット、プッシュ、PR の作成、マージは一切行いません。候補のファイルを `src/ui-ux-pro-max/data/` に
手動で昇格させる前に、変更レポート、除外、ライセンス、関連性の指標、オフラインのゲートを
確認してください。


## 自動リリース

このリポジトリでは、semantic-release と Conventional Commits を使って GitHub のリリースを自動的に作成しています：

- `feat:` -> マイナーリリース
- `feat!:` または `BREAKING CHANGE:` -> メジャーリリース

リリースのワークフローは、GitHub のリリースにはデフォルトの `GITHUB_TOKEN` を使い、`ui-ux-pro-max-cli` を npm に公開するためにはリポジトリの `NPM_TOKEN` シークレットを使います。

## トラブルシューティング

### Claude Code で `response exceeded the ... output token maximum` と表示される

これは Claude Code の 1 回の応答に対する上限であり、UI/UX Pro Max のインストーラーや検索スクリプトのエラーではありません。まず、タスクを小さなステップに分け、大きな結果は少しずつファイルに書き出すよう Claude に依頼してください。

どうしても 1 回の応答を大きくする必要があり、使用中のモデルが対応している場合は、新しいセッションを始める前に Claude Code の出力トークンの上限を設定してください。例：

```bash
# macOS, Linux, or WSL
export CLAUDE_CODE_MAX_OUTPUT_TOKENS="64000"
claude
```

```powershell
# Windows PowerShell
$env:CLAUDE_CODE_MAX_OUTPUT_TOKENS = "64000"
claude
```

シェルの環境変数の変更は、そのシェルから起動したプログラムにしか適用されないため、変数を設定したら Claude Code を再起動してください。Claude Code は、使用中のモデルの出力上限を超える値を上限に丸めます。モデルやプロバイダーの上限はさまざまです。この値を大きくすると、レイテンシーや使用量が増えることもあり、自動コンパクションまでに使える実質的なコンテキストも少なくなります。公式の [Claude Code の環境変数のリファレンス](https://code.claude.com/docs/en/env-vars#variables)をご覧ください。


### デザインシステムのコマンドを実行すると Python が見つからない

検索スクリプトには Python 3.x が必要です。[python.org](https://www.python.org/downloads/) から、または OS のパッケージマネージャー（Homebrew、apt、winget）を使って手動でインストールしてください。AI エージェントがあなたの代わりにインストールすることはなく、代わりにあなたに依頼するよう指示されています。

### デザインシステムの出力が途中で切れる / フィールドが省略される

人が読む形式の出力では、長いフィールドは 300 文字で省略されます。省略されていない完全なデータを得るには `--json` を使ってください：

```bash
python3 .claude/skills/ui-ux-pro-max/scripts/search.py "SaaS" --domain style --json
```
