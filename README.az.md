### 192 sahəyə xas əsaslandırma qaydası

Əsaslandırma mühərriki aşağıdakı sahələr üçün ixtisaslaşmış qaydaları ehtiva edir:

| Kateqoriya | Nümunələr |
|------------|-----------|
| **Tech & SaaS** | SaaS, Micro SaaS, B2B Service, Developer Tool / IDE, AI/Chatbot Platform, Cybersecurity Platform |
| **Maliyyə** | Fintech/Crypto, Banking, Insurance, Personal Finance Tracker, Invoice & Billing Tool |
| **Səhiyyə** | Medical Clinic, Pharmacy, Dental, Veterinary, Mental Health, Medication Reminder |
| **E-ticarət** | General, Luxury, Marketplace (P2P), Subscription Box, Food Delivery |
| **Xidmətlər** | Beauty/Spa, Restaurant, Hotel, Legal, Home Services, Booking & Appointment |
| **Yaradıcı sahələr** | Portfolio, Agency, Photography, Gaming, Music Streaming, Photo/Video Editor |
| **Həyat tərzi** | Habit Tracker, Recipe & Cooking, Meditation, Weather, Diary, Mood Tracker |
| **Yeni texnologiyalar** | Web3/NFT, Spatial Computing, Quantum Computing, Autonomous Drone Fleet |

Hər qaydaya bunlar daxildir:
- **Tövsiyə olunan pattern** - Landing page strukturu
- **Üslub prioriteti** - Ən uyğun UI üslubları
- **Rəng əhval-ruhiyyəsi** - Sahəyə uyğun palitralar
- **Tipoqrafiya əhval-ruhiyyəsi** - Şriftin xarakterinə uyğunluq
- **Əsas effektlər** - Animasiyalar və interaksiyalar
- **Anti-pattern-lər** - Nəyi ETMƏMƏK lazımdır (məsələn, bankçılıq üçün "AI bənövşəyi/çəhrayı gradient-lər")

## Xüsusiyyətlər

- **79 axtarıla bilən UI üslubu (50-si aktiv)** - Glassmorphism, Claymorphism, Minimalism, Brutalism, Neumorphism, Bento Grid, Dark Mode, AI-Native UI və s.
- **192 rəng palitrası** - 192 məhsul növü ilə 1:1 uyğunlaşdırılmış sahəyə xas palitralar
- **74 şrift cütü** - Google Fonts import-ları ilə seçilmiş tipoqrafiya kombinasiyaları
- **25 qrafik növü** - Dashboard və analitika üçün tövsiyələr
- **22 texnologiya stack-i** - React, Next.js, Astro, Vue, Nuxt.js, Nuxt UI, Svelte, SwiftUI, React Native, Flutter, HTML+Tailwind, shadcn/ui, Jetpack Compose, Angular, Laravel, Three.js, JavaFX, WPF, WinUI 3, UWP, Avalonia, Uno Platform
- **119 UX qaydası** - Ən yaxşı təcrübələr, anti-pattern-lər, əlçatanlıq qaydaları, davamlı mətn düzülüşü, yığcam etiketlər və ləğv edilə bilən interaksiyalar
- **192 əsaslandırma qaydası** - Sahəyə xas dizayn sistemi yaradılması (v2.0-da YENİ)

### Davamlı mətn və yığcam UI

Təlimat başlıqlar, uzun tokenlər, chip-lər, badge-lər və yarımçıq qalan mikro-interaksiyalarla bağlı tez-tez rast gəlinən istehsalat problemlərini əhatə edir:

- Balanslaşdırılmış başlıq sətir keçidi mütərəqqi təkmilləşdirmədir, konkret sözün son sətirdə qalacağına zəmanət deyil. Dizaynlar müxtəlif en, şrift və lokallarda təbii sətir keçidi ilə də işləməlidir.
- Vacib mətn dar enlərdə, brauzer zoom-unda, mətn miqyaslanmasında və istifadəçinin məsafə tənzimləmələrində kəsilmədən yenidən düzülməlidir. Uzun URL və identifikatorlar təhlükəsiz şəkildə sətirə bölünə bilər.
- Chip və tag toplusu sətirə düzülməli və ya idarə oluna bilən `+n` açılışından istifadə etməlidir. Yığcam etiket mümkün olduqda bütöv qalmalıdır; qaçılmaz kəsilmə üçün klaviatura, kursor və toxunma istifadəçilərinə tam dəyərə əlçatan yol verilməlidir.
- Badge-in mənası yalnız rəngə əsaslanmamalıdır. İnteraktiv chip-lər native semantikaya, görünən fokusa və proqramla oxuna bilən vəziyyətə malik olmalıdır; canlı sayğaclar mənalı kontekst daşımalıdır.
- Sürətli interaksiyalar animasiyanı ləğv edə bilər, lakin son semantik vəziyyət, fokus və məzmun düzgün qalmalıdır. Vaxtlama platforma və komponentə görə seçilir, reduced-motion seçimlərinə hörmət edilir.

### Üslub taksonomiyası

Kataloq sabit ID və alias-larla dəstəklənən **79 axtarıla bilən üslub** ehtiva edir:

| Status | Say | Axtarış davranışı |
|--------|----:|-------------------|
| Active | 50 | Normal tövsiyələrə daxildir və qalereyada standart olaraq göstərilir |
| Supplemental | 29 | Dəqiq və ya açıq variant/sistem niyyəti olduqda qaytarılır; qalereyanın status filtri ilə əlçatandır |
| Deprecated | 9 | Normal sıralamadan çıxarılıb; köhnə adlar kanonik üslub və ya landing pattern-ə yönləndirilir |

Aktiv dəstə 43 ümumi vizual ailə, 2 mobil üslub, 3 rəsmi platforma/dizayn sistemi, 1 platforma materialı və 1 əsas analitika üslubunu əhatə edir. Hazırkı rəsmi sistemlər Fluent 2, Shopify Polaris və Adobe Spectrum-dur; Liquid Glass Apple platforma materialı kimi, Material 3 Expressive mobil Material variantı kimi saxlanılır, Spectrum 2 isə supplemental-dır. Landing page strukturları BM25 sıralamasında vizual üslublarla rəqabət aparmasın deyə ayrıca 34 pattern-lik landing dataset-də yerləşir.

Tam taksonomiya və mənşə məlumatlı metadata üçün [`styles.csv`](src/ui-ux-pro-max/data/styles.csv) faylına baxın.

* **Dizayn sisteminin yaradılması:** CLI vasitəsilə uyğunlaşdırılmış UI qaydalarını, pattern-ləri və məntiqi dərhal yaradın.

### 🟡 Premium versiya
* **Genişləndirilmiş brend dizayn skill-ləri:** UI/UX-dən kənara çıxaraq Brend kimliyi yaradılması, Loqo dizaynı, Korporativ kimlik proqramları (CIP), Bannerlər, Təqdimat slaydları və xüsusi ikonoqrafiyanı əhatə edir.

* **Korporativ arxitektura:** Geniş miqyaslı komanda tətbiqləri üçün qurulmuş daha əhatəli və miqyaslana bilən Design Token arxitekturası.
* **Prioritet dəstək:** Fasiləsiz tam dizayn iş axınına ehtiyacı olan komandalar və peşəkarlar üçün xüsusi texniki yardım.

[Skill-i quraşdırdıqdan](#quraşdırma) sonra tətbiqinizi AI köməkçinizdə açın və buna oxşar prompt istifadə edin. İş axını rejimində (Workflow Mode) əvvəlinə `/ui-ux-pro-max` əlavə edin.

### Dizayn sistemini saxlamaq (Master + Overrides pattern-i)

Dizayn sisteminizi sessiyalar arasında **iyerarxik əldə etmə** üçün fayllara saxlayın:

```bash
# Yaradın və design-system/myapp/MASTER.md faylına saxlayın
python3 .claude/skills/ui-ux-pro-max/scripts/search.py "SaaS dashboard" --design-system --persist -p "MyApp"

# Həmçinin səhifəyə xas override faylı yaradın
python3 .claude/skills/ui-ux-pro-max/scripts/search.py "SaaS dashboard" --design-system --persist -p "MyApp" --page "dashboard"
```

Bu, `design-system/` qovluq strukturunu yaradır:

```
design-system/
└── myapp/                  # Hər layihə üçün bir qovluq (-p "MyApp" dəyərinin slug-ı)
    ├── MASTER.md           # Qlobal əsas mənbə (rənglər, tipoqrafiya, məsafələr, komponentlər)
    └── pages/
        └── dashboard.md    # Səhifəyə xas override-lar (yalnız Master-dən fərqlər)
```

**İyerarxik əldə etmə necə işləyir:**
1. Konkret səhifə qurarkən (məsələn, "Checkout") əvvəlcə `design-system/[project-slug]/pages/checkout.md` faylını yoxlayın
2. Səhifə faylı varsa, onun qaydaları Master faylını **əvəz edir**
3. Yoxdursa, yalnız `design-system/[project-slug]/MASTER.md` istifadə olunur

**Kontekstə həssas əldə etmə prompt-u:**
```
I am building the [Page Name] page. Please read design-system/[project-slug]/MASTER.md.
Also check if design-system/[project-slug]/pages/[page-name].md exists.
If the page file exists, prioritize its rules.
If not, use the Master rules exclusively.
Now, generate the code...
```

### Kataloqun mənşəyi və yenilənməsi

Commit olunmuş kataloq xülasəsi hazırda **1,934 təsdiqlənmiş Google Fonts** və rəsmi lisenziya metadata-sı uyğun gəlmədiyi üçün irəli çəkilməyən **8 yoxlama istisnasını** qeyd edir. İkon təlimatı **105 seçilmiş sətir** olaraq qalır (100 birbaşa Phosphor web import-u və React Native/fallback təlimatı); ayrıca **1,512 ikonluq upstream Phosphor manifesti** adları, çəkiləri və React/SSR import-larını yoxlayır və axtarış nəticələrini bütün upstream paketlə doldurmur.

Adi inkişaf və pull request CI-ı şəbəkədən asılı deyil. Snapshot hash-ları və yaradılmış say yoxlaması daxil olmaqla tam oflayn yoxlamanı bununla işə salın:

```bash
# Və ya yalnız yaradılmış kataloq xülasəsini yoxlayın:

```

Yenilənmə normallaşdırması da commit olunmuş fixture-lərlə tamamilə oflayn sınaqdan keçirilə bilər. Çıxışlar müvəqqəti namizəd qovluğuna yazılır və kanonik datanı heç vaxt əvəz etmir:

```bash
candidate_dir="$(mktemp -d)"
python3 scripts/refresh-google-fonts.py \
  --api-input src/ui-ux-pro-max/scripts/tests/fixtures/catalogs/google-api.json \
  --metadata-input src/ui-ux-pro-max/scripts/tests/fixtures/catalogs/google-metadata.json \
  --existing-csv src/ui-ux-pro-max/scripts/tests/fixtures/catalogs/google-existing.csv \
  --overrides src/ui-ux-pro-max/scripts/tests/fixtures/catalogs/google-overrides.json \
  --output-csv "$candidate_dir/google-fonts.csv" \
  --license-output "$candidate_dir/google-font-licenses.json" \
  --metadata-revision fixture-catalogs-v1 \
  --verified-at 2026-08-13 --expected-count 2 --approve-changes
python3 scripts/refresh-icon-catalog.py \
  --input src/ui-ux-pro-max/scripts/tests/fixtures/catalogs/phosphor-core.json \
  --package-json src/ui-ux-pro-max/scripts/tests/fixtures/catalogs/phosphor-package.json \
  --react-package-json src/ui-ux-pro-max/scripts/tests/fixtures/catalogs/phosphor-react-package.json \
  --react-exports-input src/ui-ux-pro-max/scripts/tests/fixtures/catalogs/phosphor-react-exports.json \
  --curated-csv src/ui-ux-pro-max/scripts/tests/fixtures/catalogs/icons-curated.csv \
  --output "$candidate_dir/phosphor-icons-upstream.json" \
  --verified-at 2026-08-13 --expected-count 2
```

Canlı upstream yenilənməsi qəsdən `refresh-catalogs.yml` workflow-unda təcrid olunub; o, bazar ertəsi günləri 03:17 UTC-də planlaşdırılıb və tələb üzrə də işə salına bilər. `GOOGLE_FONTS_API_KEY`-i GitHub Actions secret-i kimi konfiqurasiya edin, sonra işə salın və yoxlama artefaktını yükləyin:

```bash
gh workflow run refresh-catalogs.yml
run_id="$(gh run list --workflow refresh-catalogs.yml --limit 1 --json databaseId --jq '.[0].databaseId')"
gh run watch "$run_id"
gh run download "$run_id" --name "catalog-refresh-review-$run_id"
```

Workflow Google Fonts Developer API-ni və sabitlənmiş rəsmi Phosphor paketlərini oxuyur, namizədləri və unified diff-ləri artefakta yazır və repozitoriyaya yalnız oxuma icazəsinə malikdir. O, heç vaxt commit etmir, push etmir, PR açmır və ya merge etmir. Namizəd faylları `src/ui-ux-pro-max/data/` qovluğuna əl ilə irəli çəkməzdən əvvəl dəyişiklik hesabatlarını, istisnaları, lisenziyaları, uyğunluq metriklərini və oflayn yoxlamanı nəzərdən keçirin.

## Problemlərin aradan qaldırılması

### Claude Code `response exceeded the ... output token maximum` xətası verir

Bu, Claude Code-un tək cavabına qoyulan limitdir, UI/UX Pro Max quraşdırıcısında və ya axtarış skriptlərində xəta deyil. Əvvəlcə Claude-dan tapşırığı kiçik addımlara bölməyi və böyük nəticələri tədricən fayla yazmağı xahiş edin.

Həqiqətən daha böyük tək cavaba ehtiyacınız varsa və aktiv model bunu dəstəkləyirsə, yeni sessiya başlamazdan əvvəl Claude Code-un output-token limitini təyin edin. Məsələn:

```bash
# macOS, Linux və ya WSL
export CLAUDE_CODE_MAX_OUTPUT_TOKENS="64000"
claude
```

```powershell
# Windows PowerShell
$env:CLAUDE_CODE_MAX_OUTPUT_TOKENS = "64000"
claude
```

Shell mühit dəyişiklikləri yalnız həmin shell-dən başladılan proqramlara aid olur, ona görə dəyişəni təyin etdikdən sonra Claude Code-u yenidən başladın. Claude Code aktiv modelin output limitindən yuxarı dəyərləri məhdudlaşdırır; model və provayder limitləri fərqlidir. Bu dəyəri artırmaq gecikməni və istifadəni də artıra bilər, həmçinin avtomatik sıxışdırmadan əvvəlki effektiv konteksti azaldır. Rəsmi [Claude Code environment-variable reference](https://code.claude.com/docs/en/env-vars#variables) sənədinə baxın.
