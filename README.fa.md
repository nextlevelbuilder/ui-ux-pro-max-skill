## تازه‌های نسخهٔ 2.0

### تولید هوشمند سیستم طراحی

مهم‌ترین قابلیت نسخهٔ 2.0، **مولد سیستم طراحی (Design System Generator)** است؛ یک موتور استدلال مبتنی بر هوش مصنوعی که نیازمندی‌های پروژهٔ شما را تحلیل می‌کند و در چند ثانیه یک سیستم طراحی کامل و متناسب با همان پروژه می‌سازد.

نمونهٔ زیر یک سیستم طراحی پیشنهادی برای یک مرکز اسپا را نشان می‌دهد. ساختار، مقادیر و کدهای نمونه برای حفظ خوانایی و امکان مقایسه، بدون تغییر نگه داشته شده‌اند:

```text

+----------------------------------------------------------------------------------------+
|                                                                                        |

|     Conversion: Emotion-driven with trust elements                                     |
|     CTA: Above fold, repeated after testimonials                                       |
|     Sections:                                                                          |
|       1. Hero                                                                          |
|       2. Services                                                                      |
|       3. Testimonials                                                                  |
|       4. Booking                                                                       |
|       5. Contact                                                                       |

|  STYLE: Soft UI Evolution                                                              |

|     Best For: Wellness, beauty, lifestyle brands, premium services                     |
|     Performance: cost:low | Accessibility: risk:conditional; verify requirements       |
|                                                                                        |
```

### ۱۹۲ قانون استدلال متناسب با صنایع مختلف

موتور استدلال شامل قوانین تخصصی برای حوزه‌های زیر است:

| دسته‌بندی | نمونه‌ها |
|----------|----------|
| **فناوری و SaaS** | SaaS، Micro SaaS، خدمات B2B، ابزار توسعه‌دهنده / IDE، پلتفرم هوش مصنوعی و چت‌بات، پلتفرم امنیت سایبری |
| **مالی** | فین‌تک/رمزارز، بانکداری، بیمه، مدیریت مالی شخصی، ابزار صدور فاکتور و صورت‌حساب |
| **سلامت و درمان** | کلینیک پزشکی، داروخانه، دندان‌پزشکی، دامپزشکی، سلامت روان، یادآور مصرف دارو |
| **تجارت الکترونیک** | فروشگاه عمومی، فروشگاه لوکس، بازارگاه (P2P)، جعبهٔ اشتراکی، تحویل غذا |
| **خدمات** | زیبایی/اسپا، رستوران، هتل، خدمات حقوقی، خدمات منزل، رزرو و نوبت‌دهی |
| **خلاقیت** | نمونه‌کار، آژانس، عکاسی، بازی، پخش موسیقی، ویرایش عکس/ویدئو |
| **سبک زندگی** | پیگیری عادت‌ها، دستور پخت و آشپزی، مدیتیشن، آب‌وهوا، دفتر خاطرات، پیگیری خلق‌وخو |
| **فناوری‌های نوظهور** | Web3/NFT، رایانش فضایی، رایانش کوانتومی، ناوگان پهپادهای خودران |

هر قانون شامل موارد زیر است:

- **الگوی پیشنهادی (Recommended Pattern):** ساختار صفحهٔ فرود
- **اولویت سبک (Style Priority):** سبک‌های رابط کاربری که بیشترین تطابق را دارند
- **حال‌وهوای رنگ (Color Mood):** پالت‌های متناسب با صنعت
- **حال‌وهوای تایپوگرافی (Typography Mood):** شخصیت و حس‌وحال فونت
- **جلوه‌های کلیدی (Key Effects):** انیمیشن‌ها و تعامل‌ها
- **الگوهای نامناسب (Anti-Patterns):** مواردی که نباید استفاده شوند؛ برای مثال، استفاده از گرادیان‌های بنفش/صورتی هوش مصنوعی برای یک سامانهٔ بانکداری

## قابلیت‌ها

- **۷۹ سبک رابط کاربری قابل جست‌وجو (۵۰ سبک فعال):** از جمله Glassmorphism، Claymorphism، Minimalism، Brutalism، Neumorphism، Bento Grid، Dark Mode، AI-Native UI و موارد دیگر
- **۱۹۲ پالت رنگ:** پالت‌های اختصاصی هر صنعت که به‌صورت یک‌به‌یک با ۱۹۲ نوع محصول هماهنگ شده‌اند
- **۷۴ ترکیب فونت:** ترکیب‌های گزینش‌شدهٔ تایپوگرافی همراه با امکان واردکردن فونت از Google Fonts
- **۲۵ نوع نمودار:** پیشنهادهایی برای داشبوردها و تحلیل داده
- **۲۲ پشتهٔ فناوری:** React، Next.js، Astro، Vue، Nuxt.js، Nuxt UI، Svelte، SwiftUI، React Native، Flutter، HTML+Tailwind، shadcn/ui، Jetpack Compose، Angular، Laravel، Three.js، JavaFX، WPF، WinUI 3، UWP، Avalonia و Uno Platform
- **۱۱۹ راهنمای UX:** بهترین روش‌ها، الگوهای نامناسب، قواعد دسترس‌پذیری، چیدمان مقاوم متن، برچسب‌های فشرده و تعامل‌های قابل لغو
- **۱۹۲ قانون استدلال:** تولید سیستم طراحی متناسب با صنعت (قابلیت جدید در نسخهٔ 2.0)

### متن انعطاف‌پذیر و رابط کاربری فشرده

راهنماها اکنون خطاهای رایج محیط واقعی محصول را نیز پوشش می‌دهند؛ از جمله مشکلات عنوان‌ها، واژه‌های طولانی، چیپ‌ها، نشان‌ها و تعامل‌های کوتاه که ممکن است نیمه‌کاره قطع شوند:

- شکستن متعادل سطرهای عنوان، یک بهبود تدریجی است و تضمین نمی‌کند که واژه‌ای مشخص حتماً در آخرین خط قرار بگیرد. طراحی باید با شکستن طبیعی متن در عرض‌ها، فونت‌ها و زبان‌های مختلف نیز درست کار کند.
- متن‌های ضروری نباید در عرض‌های کم، بزرگ‌نمایی مرورگر، تغییر مقیاس متن یا تنظیم فاصله‌گذاری توسط کاربر بریده شوند. نشانی‌های اینترنتی و شناسه‌های طولانی باید بتوانند به‌شکل ایمن به سطر بعد منتقل شوند.
- مجموعهٔ چیپ‌ها و برچسب‌ها باید به سطر بعد منتقل شوند یا امکان نمایش موارد بیشتر با گزینه‌ای مانند `+n` داشته باشند. در صورت امکان، برچسب فشرده باید کامل نمایش داده شود؛ اگر کوتاه‌سازی اجتناب‌ناپذیر است، کاربران صفحه‌کلید، ماوس و صفحهٔ لمسی باید راهی دسترس‌پذیر برای مشاهدهٔ مقدار کامل داشته باشند.
- معنای نشان‌ها نباید فقط به رنگ وابسته باشد. چیپ‌های تعاملی باید معنای بومی و استاندارد، حالت تمرکز قابل مشاهده و وضعیت قابل تشخیص برای فناوری‌های کمکی داشته باشند؛ شمارنده‌های زنده نیز باید زمینهٔ معناداری ارائه کنند.
- تعامل‌های سریع ممکن است باعث لغو انیمیشن شوند، اما وضعیت معنایی نهایی، تمرکز و محتوا باید همچنان صحیح باقی بمانند. زمان‌بندی باید متناسب با پلتفرم و مؤلفه انتخاب شود و ترجیح کاربر برای کاهش حرکت نیز رعایت شود.

### دسته‌بندی سبک‌ها

این کاتالوگ شامل **۷۹ سبک قابل جست‌وجو** است که با شناسه‌ها و نام‌های جایگزین پایدار پشتیبانی می‌شوند:

| وضعیت | تعداد | رفتار جست‌وجو |
|--------|------:|----------------|
| فعال (Active) | ۵۰ | در پیشنهادهای معمول قرار می‌گیرند و به‌صورت پیش‌فرض در گالری نمایش داده می‌شوند |
| تکمیلی (Supplemental) | ۲۹ | برای درخواست‌های دقیق یا اشارهٔ صریح به گونه/سیستم برگردانده می‌شوند؛ از طریق فیلتر وضعیت گالری نیز در دسترس‌اند |
| منسوخ (Deprecated) | ۹ | از رتبه‌بندی معمول کنار گذاشته شده‌اند؛ نام‌های قدیمی به سبک یا الگوی صفحهٔ فرود مرجع هدایت می‌شوند |

مجموعهٔ فعال شامل ۴۳ خانوادهٔ بصری عمومی، ۲ سبک ویژهٔ موبایل، ۴ سیستم رسمی پلتفرم/طراحی، ۱ متریال پلتفرمی و ۱ سبک اصلی تحلیل داده است. سیستم‌های رسمی فعلی شامل Fluent 2، Shopify Polaris، Adobe Spectrum و Apple Native Experience هستند؛ Liquid Glass به‌عنوان متریال پلتفرم اپل در نظر گرفته شده، Material 3 Expressive همچنان یک گونهٔ موبایلی از Material است و Spectrum 2 در گروه سبک‌های تکمیلی قرار دارد. ساختارهای صفحهٔ فرود در مجموعه‌دادهٔ جداگانه‌ای با ۳۴ الگو نگهداری می‌شوند و در رتبه‌بندی BM25 با سبک‌های بصری رقابت نمی‌کنند.

برای مشاهدهٔ دسته‌بندی کامل و فراداده‌های دارای اطلاعات منشأ، فایل [`styles.csv`](src/ui-ux-pro-max/data/styles.csv) را ببینید.

## 💎 مقایسهٔ نسخهٔ پایه و نسخهٔ پریمیوم

بسیاری از کاربران دربارهٔ تفاوت نسخهٔ متن‌باز و نسخهٔ پریمیوم سؤال می‌کنند. در ادامه جزئیات آمده است تا بتوانید نسخهٔ مناسب جریان کاری خود را انتخاب کنید.

### 🟢 نسخهٔ پایه (همین مخزن)

- **کاملاً متن‌باز:** مناسب توسعه‌دهندگان مستقل، علاقه‌مندان و پروژه‌های معمول
- **هوشمندی اصلی UI/UX:** دسترسی کامل به ۷۹ سبک قابل جست‌وجو (۵۰ سبک فعال)، ۱۹۲ نوع محصول، پالت‌های رنگ و ترکیب‌های گزینش‌شدهٔ فونت
- **پیشنهادهای هوشمند:** موتور جست‌وجوی داخلی BM25 برای تطبیق دقیق طراحی
- **پشتیبانی چندپلتفرمی:** راهنماهای اختصاصی برای ۲۲ فریم‌ورک و فناوری اصلی (React، Vue، Tailwind، iOS، Android و غیره)
- **تولید سیستم طراحی:** تولید فوری قوانین، الگوها و منطق UI متناسب با پروژه از طریق CLI

### 🟡 نسخهٔ پریمیوم

- **مهارت‌های گسترده‌تر طراحی برند:** فراتر از UI/UX؛ شامل تولید هویت برند، طراحی لوگو، برنامه‌های هویت سازمانی (CIP)، بنر، اسلاید ارائه و طراحی آیکون اختصاصی
- **ساخت پیشرفتهٔ دارایی‌های بصری:** یکپارچگی عمیق با تولید تصویر مبتنی بر هوش مصنوعی برای ساخت دارایی‌های بصری واقعی، نه صرفاً تصاویر جایگزین
- **معماری سازمانی:** معماری جامع‌تر و مقیاس‌پذیرتر توکن‌های طراحی، مناسب استقرار در تیم‌های بزرگ
- **پشتیبانی اولویت‌دار:** کمک فنی اختصاصی برای تیم‌ها و متخصصانی که به جریان کاری طراحی کامل و بدون وقفه نیاز دارند

### اعمال یک تم روی برنامهٔ موجود

پس از [نصب مهارت](#نصب)، برنامهٔ خود را در دستیار هوش مصنوعی باز کنید و درخواستی مشابه نمونهٔ زیر بدهید. در حالت Workflow، عبارت `/ui-ux-pro-max` را در ابتدای درخواست قرار دهید.

```text
Use the ui-ux-pro-max skill to retheme my existing React app.
Target style: Minimalism & Swiss Style.
First inspect the framework and styling-library versions, routes, components,
styles, and existing theme tokens. Keep the current component structure,
behavior, and business logic.
Reuse and update the existing semantic tokens for colors, typography, spacing,
radii, shadows, and interaction states; add missing tokens rather than creating
a parallel theme system. Replace hard-coded styles one component at a time.
Verify contrast, keyboard focus, responsive layouts, and all supported light/dark
modes. Summarize changed files and any remaining hard-coded styles.
```

عبارت `Minimalism & Swiss Style` را با سبک دلخواه خود از [کاتالوگ سبک‌ها](src/ui-ux-pro-max/data/styles.csv) یا جهت‌گیری بصری موردنظرتان جایگزین کنید. نتایج جست‌وجو راهنمای طراحی ارائه می‌کنند؛ اما به‌صورت خودکار کد برنامهٔ شما را بازنویسی نمی‌کنند.

**چک‌لیست تغییر تم:**

- **بررسی (Audit):** مقادیر ثابت و hard-coded مرتبط با تم را در stylesheetها، استایل‌های درون‌خطی و ابزارهایی مانند `bg-blue-600` یا `text-[#1e293b]` پیدا کنید.
- **نگاشت (Map):** نقش‌های معنایی مانند `background`، `surface`، `foreground`، `primary`، `border` و `ring` را در سیستم استایل فعلی برنامه به‌کار بگیرید. نقش‌های لازم را مطابق قراردادهای نسخهٔ نصب‌شدهٔ کتابخانه اضافه کنید.
- **مهاجرت (Migrate):** مقادیر ثابت را در دسته‌های کوچک از مؤلفه‌ها با ارجاع به توکن‌ها جایگزین کنید. تغییر توکن‌ها به‌تنهایی روی استایل‌هایی که از آن‌ها استفاده نمی‌کنند اثری ندارد.
- **اعتبارسنجی (Verify):** کنتراست متن و رابط، حالت‌های hover/focus/disabled، چیدمان واکنش‌گرا و تمام تم‌های پشتیبانی‌شده را پس از هر مرحله بررسی کنید.

### سازوکار عملکرد

1. **شما درخواست می‌دهید:** هر نوع کار UI/UX را درخواست می‌کنید (ساخت، طراحی، ایجاد، پیاده‌سازی، بازبینی، رفع اشکال یا بهبود).
2. **سیستم طراحی تولید می‌شود:** هوش مصنوعی با استفاده از موتور استدلال، به‌طور خودکار یک سیستم طراحی کامل تولید می‌کند.
3. **پیشنهادهای هوشمند ارائه می‌شوند:** بر اساس نوع محصول و نیازمندی‌های شما، سبک‌ها، رنگ‌ها و تایپوگرافی مناسب انتخاب می‌شوند.
4. **کد تولید می‌شود:** رابط با رنگ‌ها، فونت‌ها، فاصله‌گذاری و بهترین روش‌های طراحی پیاده‌سازی می‌شود.
5. **بررسی‌های پیش از تحویل انجام می‌شوند:** خروجی از نظر الگوهای نامناسب رایج در UI/UX اعتبارسنجی می‌شود.

جست‌وجوی پشته‌های وب با نسخهٔ فناوری سازگار است. جست‌وجوهایی که نسخهٔ قدیمی‌تری را مشخص نمی‌کنند، راهنمای فعال و فعلی را برمی‌گردانند. عبارت‌های صریح قدیمی یا نسخه‌های پیشین (برای مثال `Svelte 4` یا `Next.js 15`) فقط ردیف‌های گزینش‌شدهٔ مربوط به نسخه‌های قدیمی را برمی‌گردانند و با برچسب‌های `Status` و `Applies To` مشخص می‌شوند. اگر راهنمای قدیمی منطبق وجود نداشته باشد، به‌جای ترکیب نسل‌های مختلف فریم‌ورک، نتیجه‌ای برگردانده نمی‌شود.

### سازگاری RTL (`--rtl`)

هر ردیف سبک و محصول دارای مقدار `rtl_level` برای رابط‌های راست‌به‌چپ (عربی، عبری، فارسی و اردو) است:

| سطح | معنی |
|-----|------|
| `full` | مستقل از جهت نوشتار است؛ چیدمان بدون تغییر خاصی پس از آینه‌ای‌شدن نیز درست کار می‌کند. |
| `partial` | به‌خوبی آینه‌ای می‌شود، اما برخی مؤلفه‌ها و حرکت‌ها به تنظیم نیاز دارند. |
| `caveats` | سبک یا محصول به جهت خواندن وابسته است؛ مانند تایپوگرافی جنبشی، خط زمانی چپ‌به‌راست، محیط کد/ترمینال، نقشه‌ها و ترتیب صندلی‌ها. |

```bash
# Only styles that mirror without extra work
python3 .claude/skills/ui-ux-pro-max/scripts/search.py "dashboard" --domain style --rtl=full

# All levels, filtered results still tagged with rtl_level
python3 .claude/skills/ui-ux-pro-max/scripts/search.py "mobile" --domain style --rtl
```

گزینهٔ `--rtl` به تعیین صریح `--domain style` یا `--domain product` نیاز دارد. فیلتر پس از رتبه‌بندی و پیش از محدودسازی نتایج با `-n/--max-results` اعمال می‌شود؛ بنابراین محدودیت تعداد نتایج، ردیف منطبق را پنهان نمی‌کند. استفاده از آن همراه با `--design-system` و `--stack` مجاز نیست.

### ذخیرهٔ سیستم طراحی (الگوی Master + Overrides)

سیستم طراحی خود را برای **بازیابی سلسله‌مراتبی در نشست‌های مختلف** در فایل‌ها ذخیره کنید:

```bash
# Generate and persist to design-system/myapp/MASTER.md
python3 .claude/skills/ui-ux-pro-max/scripts/search.py "SaaS dashboard" --design-system --persist -p "MyApp"

# Also create a page-specific override file
python3 .claude/skills/ui-ux-pro-max/scripts/search.py "SaaS dashboard" --design-system --persist -p "MyApp" --page "dashboard"
```

این فرمان ساختار پوشهٔ `design-system/` را ایجاد می‌کند:

```text
design-system/
└── myapp/                  # One folder per project (slug of -p "MyApp")
    ├── MASTER.md           # Global Source of Truth (colors, typography, spacing, components)
    └── pages/
        └── dashboard.md    # Page-specific overrides (only deviations from Master)
```

**بازیابی سلسله‌مراتبی چگونه کار می‌کند؟**

1. هنگام ساخت یک صفحهٔ مشخص (برای مثال «Checkout»)، ابتدا فایل `design-system/[project-slug]/pages/checkout.md` را بررسی کنید.
2. اگر فایل صفحه وجود داشته باشد، قوانین آن بر فایل Master **اولویت دارند**.
3. اگر فایل صفحه وجود نداشته باشد، فقط از `design-system/[project-slug]/MASTER.md` استفاده کنید.

**نمونهٔ درخواست برای بازیابی آگاه از زمینه:**

```text
I am building the [Page Name] page. Please read design-system/[project-slug]/MASTER.md.
Also check if design-system/[project-slug]/pages/[page-name].md exists.
If the page file exists, prioritize its rules.
If not, use the Master rules exclusively.
Now, generate the code...
```

برای راهنمای کامل توسعه، فایل [CLAUDE.md](CLAUDE.md) را ببینید.

### منشأ کاتالوگ و به‌روزرسانی آن

خلاصهٔ کاتالوگ ثبت‌شده در مخزن در حال حاضر شامل **۱٬۹۳۴ فونت تأییدشدهٔ Google Fonts** به‌علاوهٔ **۸ مورد کنارگذاشته‌شده برای بازبینی** است که تا زمان تطبیق با فرادادهٔ رسمی مجوز، وارد مجموعهٔ اصلی نمی‌شوند. راهنمای آیکون همچنان شامل **۱۰۵ ردیف گزینش‌شده** است (۱۰۰ مورد واردسازی مستقیم Phosphor برای وب به‌علاوهٔ راهنمای React Native و روش جایگزین). مانیفست جداگانهٔ **۱٬۵۱۲ آیکونی Phosphor در منبع بالادستی**، نام‌ها، وزن‌ها و واردسازی React/SSR را اعتبارسنجی می‌کند، بدون آنکه تمام بستهٔ بالادستی را وارد نتایج جست‌وجو کند.

توسعهٔ معمول و CI درخواست‌های ادغام، مستقل از شبکه هستند. برای اجرای کامل بررسی آفلاین، همراه با هش snapshotها و اعتبارسنجی تعداد داده‌های تولیدشده، دستور زیر را اجرا کنید:

```bash
npm --prefix cli run verify:data
# Or check only the generated catalog summary:
npm --prefix cli run validate:catalog-summary
```

نرمال‌سازی فرایند به‌روزرسانی را می‌توان به‌طور کامل و آفلاین و با fixtureهای ثبت‌شده نیز آزمایش کرد. خروجی‌ها در یک پوشهٔ موقت کاندید قرار می‌گیرند و هرگز جایگزین داده‌های اصلی نمی‌شوند:

```bash
candidate_dir="$(mktemp -d)"
python3 scripts/refresh-google-fonts.py \
  --api-input src/ui-ux-pro-max/scripts/tests/fixtures/catalogs/google-api.json \
  --metadata-input src/ui-ux-pro-max/scripts/tests/fixtures/catalogs/google-metadata.json \
  --existing-csv src/ui-ux-pro-max/scripts/tests/fixtures/catalogs/google-existing.csv \
  --overrides src/ui-ux-pro-max/scripts/tests/fixtures/catalogs/google-overrides.json \
  --output-csv "$candidate_dir/google-fonts.csv" \
  --license-output "$candidate_dir/google-font-licenses.json" \
  --metadata-revision fixture-catalogs-v1 \
  --verified-at 2026-08-13 --expected-count 2 --approve-changes
python3 scripts/refresh-icon-catalog.py \
  --input src/ui-ux-pro-max/scripts/tests/fixtures/catalogs/phosphor-core.json \
  --package-json src/ui-ux-pro-max/scripts/tests/fixtures/catalogs/phosphor-package.json \
  --react-package-json src/ui-ux-pro-max/scripts/tests/fixtures/catalogs/phosphor-react-package.json \
  --react-exports-input src/ui-ux-pro-max/scripts/tests/fixtures/catalogs/phosphor-react-exports.json \
  --curated-csv src/ui-ux-pro-max/scripts/tests/fixtures/catalogs/icons-curated.csv \
  --output "$candidate_dir/phosphor-icons-upstream.json" \
  --verified-at 2026-08-13 --expected-count 2
```

به‌روزرسانی زندهٔ منابع بالادستی عمداً در جریان کاری `refresh-catalogs.yml` جدا شده است. این جریان هر دوشنبه ساعت 03:17 UTC طبق برنامه اجرا می‌شود و اجرای دستی آن نیز امکان‌پذیر است. مقدار `GOOGLE_FONTS_API_KEY` را به‌عنوان secret در GitHub Actions تنظیم کنید، سپس جریان را اجرا کرده و خروجی بازبینی آن را دریافت کنید:

```bash
gh workflow run refresh-catalogs.yml
run_id="$(gh run list --workflow refresh-catalogs.yml --limit 1 --json databaseId --jq '.[0].databaseId')"
gh run watch "$run_id"
gh run download "$run_id" --name "catalog-refresh-review-$run_id"
```

این جریان، Google Fonts Developer API و بسته‌های رسمی و نسخه‌ثابت Phosphor را می‌خواند، فایل‌های کاندید و diffهای یکپارچه را در یک artifact می‌نویسد و فقط مجوز خواندن مخزن را دارد. این فرایند هرگز commit یا push انجام نمی‌دهد، درخواست ادغام باز نمی‌کند و چیزی را ادغام نمی‌کند. پیش از انتقال دستی فایل‌های کاندید به `src/ui-ux-pro-max/data/`، گزارش تغییرات، موارد کنارگذاشته‌شده، مجوزها، معیارهای مرتبط‌بودن و بررسی آفلاین را بازبینی کنید.

## انتشارهای خودکار

این مخزن برای ایجاد خودکار نسخه‌های GitHub از semantic-release همراه با Conventional Commits استفاده می‌کند:

- شاخهٔ `dev` نسخه‌های آزمایشی GitHub مانند `2.6.0-beta.1` ایجاد می‌کند.
- شاخهٔ `main` نسخه‌های پایدار رسمی GitHub مانند `2.6.0` ایجاد می‌کند.

یادداشت‌های انتشار و فایل `CHANGELOG.md` از پیام‌های Conventional Commit تولید می‌شوند. شمارهٔ نسخه‌ها هنگام آماده‌سازی انتشار، در فایل‌های `skill.json`، `.claude-plugin/plugin.json`، `.claude-plugin/marketplace.json`، `cli/package.json` و `cli/package-lock.json` همگام‌سازی می‌شوند.

برای افزایش صحیح شمارهٔ نسخه، از انواع commit زیر استفاده کنید:

- `fix:` ← انتشار patch
- `feat:` ← انتشار minor
- `feat!:` یا `BREAKING CHANGE:` ← انتشار major

جریان انتشار برای انتشارهای GitHub از `GITHUB_TOKEN` پیش‌فرض و برای انتشار بستهٔ `ui-ux-pro-max-cli` در npm از secret مخزن با نام `NPM_TOKEN` استفاده می‌کند.

## عیب‌یابی

### Claude Code پیام `response exceeded the ... output token maximum` را گزارش می‌کند

این پیام محدودیت تعداد توکن خروجی در یک پاسخ Claude Code است و به معنی وجود خطا در نصب‌کننده یا اسکریپت‌های جست‌وجوی UI/UX Pro Max نیست. ابتدا از Claude بخواهید کار را به مراحل کوچک‌تر تقسیم کند و خروجی‌های بزرگ را به‌صورت تدریجی در فایل‌ها بنویسد.

اگر واقعاً به یک پاسخ واحد و بزرگ‌تر نیاز دارید و مدل فعال از آن پشتیبانی می‌کند، پیش از شروع یک نشست جدید، محدودیت توکن خروجی Claude Code را تنظیم کنید. برای نمونه:

```bash
# macOS, Linux, or WSL
export CLAUDE_CODE_MAX_OUTPUT_TOKENS="64000"
claude
```

```powershell
# Windows PowerShell
$env:CLAUDE_CODE_MAX_OUTPUT_TOKENS = "64000"
claude
```

تغییرات محیطی shell فقط روی برنامه‌هایی اثر می‌گذارند که از همان shell اجرا می‌شوند؛ بنابراین پس از تنظیم متغیر، Claude Code را دوباره اجرا کنید. Claude Code مقادیر بالاتر از سقف خروجی مدل فعال را محدود می‌کند؛ سقف مدل و ارائه‌دهنده متفاوت است. افزایش این مقدار می‌تواند زمان پاسخ و میزان مصرف را نیز افزایش دهد و فضای زمینهٔ مؤثر پیش از فشرده‌سازی خودکار را کاهش دهد. برای جزئیات، [مستندات رسمی متغیرهای محیطی Claude Code](https://code.claude.com/docs/en/env-vars#variables) را ببینید.

### فرمان `uipro: unknown command 'uninstall'` یا `unknown command 'update'` نمایش داده می‌شود

نسخهٔ نصب‌شدهٔ `ui-ux-pro-max-cli` قدیمی است. آن را به‌روزرسانی و دوباره تلاش کنید:

```bash
npm install -g ui-ux-pro-max-cli@latest
uipro uninstall
```

### فرمان `uipro uninstall` پیام `No installed AI skill directories detected` را نشان می‌دهد

مهارت در پوشه‌ای متفاوت از مسیری نصب شده که اکنون فرمان را از آن اجرا می‌کنید. یکی از روش‌های زیر را انتخاب کنید:

```bash
# Option A — run from the project root where you originally installed it
cd /path/to/your/project
uipro uninstall

# Option B — remove the global install
uipro uninstall --global

# Option C — remove manually
rm -rf .claude/skills/ui-ux-pro-max   # Claude Code
rm -rf .cursor/skills/ui-ux-pro-max   # Cursor
rm -rf .windsurf/skills/ui-ux-pro-max # Windsurf
rm -rf .agents/skills/ui-ux-pro-max   # Antigravity / Codex
```

### پنجرهٔ «Upload a skill» در Claude.ai پیام `Zip contains too many files (maximum 200)` را نشان می‌دهد

فایل ZIP کامل مخزن GitHub را بارگذاری نکنید. این فایل یک نسخهٔ توسعه‌ای از مخزن است که کد منبع، دارایی‌های CLI، مستندات، پیش‌نمایش‌ها و چند مهارت بسته‌بندی‌شده را در بر دارد؛ بنابراین از محدودیت ۲۰۰ فایل Claude بیشتر می‌شود. این فایل، خروجی مناسب بارگذاری مهارت در Claude نیست و این پروژه در حال حاضر ZIP جداگانه‌ای برای بارگذاری دستی در Claude.ai منتشر نمی‌کند.

برای Claude Code، از Marketplace نصب کنید:

```bash
/plugin marketplace add nextlevelbuilder/ui-ux-pro-max-skill
/plugin install ui-ux-pro-max@ui-ux-pro-max-skill
```

یا از نصب‌کنندهٔ CLI استفاده کنید:

```bash
npx ui-ux-pro-max-cli init --ai claude
```

### نصب از Claude Marketplace با خطای `Zip file contains a symbolic link` مواجه می‌شود

این مشکل در نسخه‌های پیش از v2.5.1 شناخته‌شده است. مخزن در گذشته از symlinkها به‌صورت داخلی استفاده می‌کرد که برخی ابزارهای نصب قادر به پردازش آن‌ها نبودند. **راه‌حل:** به‌جای آن از نصب‌کنندهٔ CLI استفاده کنید:

```bash
npm install -g ui-ux-pro-max-cli
uipro init --ai claude
```

یا تا انتشار نسخه‌ای که این مشکل در آن برطرف شده است صبر کنید.

### فرمان `npm install -g ui-ux-pro-max-cli` با خطای مجوز اجرا نمی‌شود

استفاده از مدیر نسخهٔ Node (روش پیشنهادی) یا صرف‌نظرکردن از نصب سراسری، دو راه ممکن هستند:

```bash
# npx without installing globally
npx ui-ux-pro-max-cli init --ai claude
```

### هنگام اجرای فرمان‌های سیستم طراحی، Python پیدا نمی‌شود

اسکریپت‌های جست‌وجو به Python 3.x نیاز دارند. آن را به‌صورت دستی از [python.org](https://www.python.org/downloads/) یا با مدیر بستهٔ سیستم‌عامل خود (Homebrew، apt یا winget) نصب کنید. عامل‌های هوش مصنوعی نباید این نرم‌افزار را به‌جای شما نصب کنند؛ طبق دستورالعمل، ابتدا باید از شما درخواست کنند.

### خروجی سیستم طراحی بریده می‌شود یا بعضی فیلدها ناقص هستند

خروجی قابل خواندن برای انسان، فیلدهای طولانی‌تر از ۳۰۰ نویسه را کوتاه می‌کند. برای دریافت دادهٔ کامل و بدون کوتاه‌سازی، از گزینهٔ `--json` استفاده کنید:

```bash
python3 .claude/skills/ui-ux-pro-max/scripts/search.py "SaaS" --domain style --json
```
